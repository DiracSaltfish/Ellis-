# Luna 独立执行任务书 v1.0

## 目标与最终边界

用户指定模型 gpt-5.6-luna、推理 xhigh。自行持续推进本任务，无需主 Agent 在线，也不需要向主 Agent 发送日常进度。完成后在本任务提交交付入口和简短结论，等用户唤醒主 Agent 验收。不得创建其他任务、子 Agent、定时自动化或自行更换模型。

本轮目标：将已验证的 520600 一分钟价格风险研究适配为可配置、可断点恢复的批处理，处理种子目录的全部 210 条候选。逐条核查基金分类与数据覆盖，对符合研究范围且数据足够的基金完成固定回测和敏感性分析；其余逐条交付有证据的排除或阻塞原因。210 是候选目录数量，不是已认证港股通 ETF 数量。不要声称覆盖全市场，也不在本轮无限扩充种子目录。

目录快照：原项目 data/inventory/candidate_universe.csv。固定窗口 2026-03-03 至 2026-08-03；默认纯港股、港股通渠道基金。QDII 仅登记为范围外，A/H 混合基金登记为需要另一套估值实现，不擅自用香港篮子代表全基金。沪/深通道须有依据，代码交易所不等于投资通道。

- 从原项目定向复制 scripts、tests、config、docs、README、requirements 文件到 worktree；发现同名已有修改时先比对，保留它们。原项目 data/raw、data/normalized、data/inventory、reports、notebooks 可作为只读输入或复制到隔离的基准复现目录。不得复制整个父项目、.git、.venv 或整个远程硬盘。
- 可复用原项目 `.venv/bin/python` 解释器，缺依赖时在自己 worktree 创建环境。共享原始文件不能被新程序输出路径覆盖；只读符号链接只允许指向输入文件，不允许将可写的 data 或 reports 整目录链接到基准。

## 按顺序推进

### G01 建立工作区与锁定输入
读取本任务书、WORKBOOK_CONTRACT.md、schema.json、原项目 docs/STANDARD_WORKFLOW.md、config/pilot.json、README、data/inventory/remote_inventory.json。先使用可用的 codebase-memory 图工具发现代码，图无匹配再用文件搜索。建立 LOCATION.json、输入 manifest、210 条候选的唯一键检查。不重新递归扫描慢速挂载盘。

### G02 独立复现 520600
在隔离输出中使用既有缓存运行原实现、5 项测试、验证脚本。对照原 reports/model_comparison.csv、results.json、validation.json 逐模型逐周期比较，不只比较四舍五入摘要。97 个有效日、37 个 OOS 日；30 分钟 HHI+HTI 标准差约 19.430026 bp、方差降低约 0.722843。固定种子及相同输入下计数必须完全一致，确定性浮点指标绝对误差不超过 1e-8，报告近似值不作精确 oracle。差异查明前不能批跑，禁止为通过而改写原 oracle。Bootstrap 若实现或随机序列不同，先保留原实现复现，再将差异作为版本变更解释。

### G03 参数化与回归验证
将基金代码、日期、交易通道、FX 来源、数据/输出根目录、事件策略、工具集合、真实合约映射、训练窗口与随机种子变成实际生效的配置/CLI。不能只修改 config JSON 而脚本仍硬编码 520600。520600 使用新实现重跑，结果按 G02 复核；再选择覆盖最多的一只已核实同范围基金做冒烟运行，覆盖不足则选下一只。通过后冻结方法配置和代码快照，再进行大批量执行。实现故障修复可继续，必须记录版本并重跑受影响标的；不得见 OOS 结果后调参并冒充原计划。

### G04 全部候选分类及覆盖盘点
逐条查询基金公司/交易所/指数官方资料，保留具体 URL、抓取时间、关键事实、通道依据；名称相似不能作认证。先复用缓存，必要时只对日级 PCF 文件建立一次批量索引，每个日期文件只读一次，记录各基金有效 PCF 日期和成分并集。同批股票增量合并抓取，避免每只基金重新解压相同日包。输出完整候选分母、分类结果及可跑队列。先跑 520600，再按有效日降序、同日数按基金代码升序。不得根据外测表现排序执行或排除标的。

### G05 执行逐基金任务 F-{fund_id}
每只基金内部固定五步，并在任务日志追加子任务 ID：S1 分类与输入；S2 证券事件与分钟面板；S3 固定模型外测；S4 敏感性与独立核验；S5 报告与台账。每完成一步原子更新 ledger、Excel、checkpoint，再继续下一步。基金总任务只有五步产物齐全才可完成。

60 个训练日 + 至少 20 个 OOS 有效日是本轮运行样本门槛，不是统计显著性保证。不足 80 个有效日，标记 INSUFFICIENT_HISTORY，不缩短训练窗口凑结果。不足项仍记录实际可用日与最早/最晚日。单只阻塞继续其他基金；依赖故障影响整批时先处理共有原因。

### G06 汇总与验收
全部候选必须有终态且分母可核对。按基金、周期、模型输出明细；跨基金日期不同不得直接混为严格收益排名。列出简单基准、复杂选模、双腿相对单腿边际改善、尾部及敏感性，允许结论为无可靠对冲。完成全部固定 QA、Excel 字段校验、汇总计数对账和至少 3 个代表性基金逐值抽查。提交 FINAL_HANDOFF.md，列出完成/范围外/数据不足/证据不足/技术阻塞数量、代码位置、一条重跑命令、Excel 位置、局限与主 Agent 验收顺序。存在阻塞时写清本轮未完成回测的范围，不把整批标为全成功。

3. 汇率与已有期货参考 `/Users/ellis/newnavnav/港股通汇率研究`；卖出结算率对应买港股支出，买入结算率对应卖出港股收入。只能使用已确认通道的对应汇率，不能凭上市交易所猜。日终率不可作为当日已知信号；缺 FX 时可完成 HKD 价格风险分析，人民币估值留空并明确局部缺口，不能冒用沪率代深率。
4. TWS 127.0.0.1:7496 只读历史行情。复用缓存与已确认 HSI/HHI/HSTECH 合约；不读取账户、不下单、不修改 TWS/采集服务配置。串行历史请求、唯一 clientId、断点缓存，遇 pacing 按返回信息退避。
5. 停复牌、拆股、临时代码、代码重用、复杂权益由你查询。关键异常使用 HKEX 或发行人公告；二级事件接口只能筛查。无价格不等于停牌，冻结价格不等于经济风险为零。复杂权益不能估值则剔除整个基金日，不删成分重归一。普通拆股使用每日真实 PCF 数量及当日未复权价格，不重复调整。保存 unknown，不编造全事件完备。
6. 沿用 13:00—14:59 分钟标签、下一分钟可用、同日固定数量收益、5/15/30/60 分钟、60 日滚动训练、前 50 后 10 日内验证、下一日 OOS。禁止后向填充、跨日/午休/合约拼接和 ETF 市价替代 PCF 风险目标。

8. 每基金允许基于官方跟踪指数提出新增工具研究建议，登记候选映射表；本轮不因新增建议无限扩展采集/改模型。没有实测的工具标为 proposed_only，不给效果数。
9. 沿用最多两腿、同指数互斥、每腿 beta 0—2、总和≤2.5、Ridge alpha 0/0.01/0.1、验证 RMSE+0.2×较大方向 ES95；无截距收益、不对冲可选。保留不对冲、可用单腿、HHI+HTI 和自动选择。名义权重不是合约张数。
10. 必做陈旧≤2%/5%评价、≤2%重拟合、冻结权重时间偏移±1分钟、剔除停牌日重拟合；无停牌时明确 N/A 原因，样本不足的场景明确不足不硬算。按完整日 bootstrap，不把重叠标签当独立交易。
11. 不因收益不好、方差下降为负、尾部恶化而删基金或改检验窗口。费用未建模，结论只能是价格风险研究，不得写净套利收益或保证损失封顶。

## 自主推进、失败与资源规则

- 正常可逆工作自行完成，不为已经授权的取数、读文件、事件核验反复提问。需要用户新凭证/付费/新权限时只记录问题并继续独立任务，不猜凭证。
- 本机与远端抽取各最多 1 个重任务；公开网页最多 3 个并发，TWS 串行。不能启动多个重复批处理。按小批增量复用股票缓存，处理完一个日期即释放内存。
- 同一数据请求最多 3 次尝试；每次记录错误和改变的处理方式，明确永久失败不重试。可用第二个官方/公开来源作替代。三次失败仍不可解则将受影响步骤标 BLOCKED 或证据不足，继续其余项。不能将瞬时网络失败写成基金不合格。
- 结构性问题最多做两种有依据的修复尝试；失败保存最小复现、日志、影响范围及下一步。技术阻塞和范围排除是不同状态，不混用。
- 进度写 CURRENT_STATUS.md 与 checkpoint.jsonl。上下文压缩后从 checkpoint 和依赖表恢复，不重跑已通过且输入指纹不变的任务。不得伪造开始/结束时间，状态 RUNNING 仅对应当前实际工作。
- 每阶段和每只基金结束更新 Excel；数值空缺用 null/空白，不能用 0、字符串 N/A 或上一基金结果替代。终态记录必须含结论、依据、产物路径及 QA/问题引用。
- 不做破坏性清理、提交/推送/合并、发布、交易、购买数据或修改原采集服务。用户本次授权的是独立研究与交付。
- 不因工作量大而只做若干样例就宣称完成。最终逐条给 210 个候选交代；若平台中断，保存可恢复状态，不伪造完成。
