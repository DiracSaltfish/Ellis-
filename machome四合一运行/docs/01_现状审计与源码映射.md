## 4. 现状中必须显式处理的问题

1. **版本不可证明**：除 Webull 源文件外，其余生产二进制/脚本不能由一个干净提交完全重建。
2. **多重监管风险**：launchd、旧 GUI、自建 supervisor 不能同时拥有同一进程；尤其溢价率 console 与 hub-agent、实时申赎旧 standalone server 与内嵌 server。
3. **存活不等于可用**：几个 `/health` 都偏 liveness；首页必须计算 schedule-aware readiness/freshness。
4. **LAN 数据口不是管理口**：6787、8421、19195 都不能扩展成任意生命周期控制面。
5. **现有阻塞必须隔离**：同步 uploader、Playwright、Wind/LLDB、日志全量读取、历史大表和磁盘写均不得进入统一 UI 线程。
6. **凭据治理**：源码中存在历史硬编码/编码凭据模式；新工程只记录环境变量名或 Keychain key，不复制值。
