# 14｜2026-08-27 局域网与详情长连验证

## 验证边界

本次由开发机 `192.168.1.23` 通过局域网地址访问 machome `192.168.1.113`。自动化客户端和实际 B 均强制使用 `--read-only`，没有连接后执行任何申购、赎回、卖出或撤单操作。测试发生在午休，盘中持续消息率使用 11:28:13–11:31:00 的真实留存快照补充计算。

## 结论

- A 的 `8421`、`19195` 均可从开发机建立 TCP 连接；服务端确实监听 `0.0.0.0`，不是只接受 loopback。
- 8421 summary/detail 两条 WebSocket 在 5 分钟观察中断线 0 次，60 次主动 ping 全部收到 pong。
- detail 订阅后 5–9 ms 返回缓存十档；午休仍收到 5 次后续 TGW 主动快照。真实盘中留存显示 159866.SZ 的更新间隔中位数约 3.016 秒。
- 当前 202 标的、少量 B 客户端的 JSON 主推数据量很小，不需要为了局域网带宽改成二进制或压缩协议。
- 原 release build 从终端直接启动可正常访问 A，但通过 LaunchServices/Finder 打开时受 macOS 局域网隐私策略阻断；当时 Info.plist 缺少 `NSLocalNetworkUsageDescription`，build bundle 也只有 linker ad-hoc 状态。
- 12:17 已按当前源码重建 `dist/macos-arm64` 和 zip：新增局域网用途声明、完整 ad-hoc bundle 签名，并确认 B 识别 `--settings`、`--read-only`。发布包 B 以只读方式实际连通 A；Finder 首次授权仍必须由操作者本人完成。

## 盘中数据量估算

11:28:13–11:31:00 的真实标准化留存共有 5,273 条事件、204 个短时出现标的：

- 平均 31.575 条/s，按有事件秒统计中位数 25 条/s，峰值 123 条/s；
- 标准化持久化 JSON 平均约 34.8 KB/s；
- A→B summary 实测平均约 616 字节/条，因此盘中平均约 19.5 KB/s/客户端，瞬时峰值估算约 75.8 KB/s/客户端；
- 159866.SZ 在 105 秒内 31 帧，约 0.295 帧/s；按 detail 约 1.14 KB/帧估算，仅约 0.34 KB/s/打开的详情页。

当前 1–3 台 B 时无需网络协议优化。若以后达到以下任一条件，再启用服务端 summary 合并、二进制 Protobuf 或压缩：单客户端持续超过 1 MB/s、真实 B 超过 10 台且 A 网络线程 CPU 明显上升、`monitor_slow_client_drops>0`、发送积压持续非零。B 已有 100 ms UI 合并，它降低界面重绘成本，但不改变网络原始消息率。

## 实际 B 结果与打包缺陷

最新版 release build 通过终端启动：

```bash
build/macos-arm64-release-make/etf-premium-client.app/Contents/MacOS/etf-premium-client \
  --server ws://192.168.1.113:8421 \
  --config config/app.example.json \
  --settings runtime/lan-client-test.json \
  --read-only
```

实际 UI 显示 `A 已连接`、`就绪 202`，summary/detail 两条 TCP 均为 `ESTABLISHED`；观察期 B 约 3% CPU，未出现彩虹圈。测试结束后已关闭本机只读 B 并删除临时设置，machome 上的生产 A/adapter/B 未停止。

同一 build `.app` 用 `open`/Finder 启动时，两条连接长期停在 `SYN_SENT`，而同机 Python、`nc` 及终端直启 B 同时均能建立连接。包检查结果：Info.plist 没有 `NSLocalNetworkUsageDescription`，build 签名显示 `Info.plist=not bound`。因此根因位于 macOS App 打包/局域网权限，不在 A、路由或 Qt 业务协议。

本轮重打包已完成第 1、2、4、5 项；第 3 项必须由操作者本人完成：

1. 客户端 Info.plist 提供清晰的局域网用途说明；
2. `macdeployqt` 后对整个 bundle 重新签名，`codesign` 显示标识为 `com.ellis.etf-premium.client` 且 Info.plist 已绑定；
3. Finder 首次启动时由操作者本人选择允许局域网访问；自动化不得代替批准；
4. 再次按本文方法从 Finder 启动并确认两条连接均为 `ESTABLISHED`；
5. 重新生成 zip，确认其中 B 识别 `--settings` 和 `--read-only`。
