# 2026-08-27 额外 L1 热维护与深港通实施验收

发布候选版本：`0.2.0`。

## 实施边界

- A-console 在「观察标的管理」右侧增加同级「额外L1行情维护标的」页签，支持 SH/SZ/HK 增删和重叠角色显示。
- 观察列表仍只接受沪深六位代码；热维护列表额外接受精确 `02800.HK` 形式。
- Core 是两份配置的唯一持久化权威。Console 不再先写文件；Core 以容量事务 + `QSaveFile` 保存，失败时回滚 Legacy 引用和 UI。
- 观察/热维护/19195 动态引用合并为唯一 upstream set，不重复订阅。观察资格优先，仅观察标的进 8421 B 端、信号引擎和行情分区。
- adapter 重连、序列断档、上游释放或观察角色变化都会推进发布代次；旧工作队列的迟到结果在主线程发布前被丢弃，不能在移除/重加或收盘切换后泄漏旧信号。
- B 端与 8421 协议没有扩展港股；这是有意的隔离，保证热维护标的不被误当成溢价率观察标的。

## 深港通数据路径

`02800.HK` 在 adapter 边界严格转换为 `SubscribeItem(code=02800, market=kSZSE, flag=kHKTSnapshot, category=0)`。普通沪深和 HKT 分组批量订阅；批次拒绝后二分隔离单标的，单标的指数退避 1–300 秒。每次 reconcile 最多 64 次 SDK Subscribe，系统性拒绝时其余标的分散退避，避免密集空转。

C++ 按 tag 16 使用独立 `MDHKTSnapshot` 数字键映射，full 建状态，delta 只能合并同 session/full 状态。业务市场存为 HK，路由必须是数字键 1 的 102；最新价取键 11，nominal 取键 8，开盘价保持 0，五档数组只接受恰好 5 个定点整数。

## 时段与状态清理

- 工作日沪深 09:15–15:00，深港通 09:30–16:00；人工 force 同时开启两组。
- 11:30 仅重置信号滚动窗口，不清 full/delta 合并状态、不退订。
- 15:00 从目标集移除 SH/SZ 但保留 HK；16:00 移除 HK。真正从目标集移除时清理该证券 parser 与快照，下次必须重新取得 full。

## 协议与持久化不变量

- 19195 仍是 NDJSON v1；`hello.defaults`、subscribe/ack/missing/l1 结构和 `books` 五档键完全保持。只扩展了 symbol 校验可接受五位 `.HK`。
- `status.hot/pinned` 是可选诊断字段，旧客户可忽略。
- 热维护-only 原始事件和标准化快照不进 `raw/normalized` 文件；只保内存最新快照、订阅结果和必要运维日志。
- 19195 动态-only 标的在最后引用的宽限期到期后同时淘汰 parser、ready 和快照缓存；重新订阅先返回 `missing` 等待新 full，防止历史动态代码令内存无界增长或发送陈旧首帧。固定观察/热维护标的在非交易时段仍保留带原始时间的最后快照。

## 已完成的边界测试

1. HKT full/delta 合并、前导零、五档、价格/volume/amount 定点比例、legacy v1 输出。
2. 错路由 101、`2800.HK`、四档数组、价位和买卖序错误隔离。
3. 15:00 只停沪深、16:00 停 HKT、周末与 force 边界。
4. adapter 沪深/HKT 分组、单 HKT 失败不阻断沪深、系统性失败 SDK 调用上限、退避期不重复订阅。
5. 19195 真 TCP 验证旧 `.SZ`、动态 `.SH`、`02800.HK`、`2800.HK` 拒绝、hot 不计 temporary、五档不添 IOPV。
6. core + adapter 双进程仿真验证：`02800.HK` 能从 19195 取缓存并持续推送，8421 不出现该 symbol，终止后解压 raw/normalized 不含 `02800`。
7. 重叠列表状态显示 hot=2、unique pinned=2、active upstream=2，证明观察标的不被重复订阅。
8. 19195 动态标的释放后重新订阅返回 missing；服务析构和重复回归无 socket 回调访问已析构容器。
9. Core bridge epoch 变化时 adapter 丢弃旧 epoch 已排队行情，序号不会因丢弃帧产生伪缺口。
