# 分模块-原理


## 2026-09-07 内网文件同步接入

新增 `monitor_sync` 原生模块，使用 Qt WebSocket 监听内网 18976，默认无需认证/TLS；Hub 管理控制仍走原本地 IPC。新模块独立线程运行，文件任务由单线程工作池处理，复用现有 Agent 生命周期。四模块配置兼容，第五模块显式启用；UI 显示五合一，原安装路径/可执行文件身份保留。

`app/modules/monitor_sync/FileStore.*` 保存原名 CSV/JSON。不可变日期和共享版本目录、commit 清单和原子 HEAD 发布构成一致版本，校验文件字节哈希与白名单，保存操作编号及结果支持重启幂等。没有新增 SQL 业务存储。每个数据根目录有服务独占锁；原有 Hub 全局审计不在本次迁移范围。

`MonitorSyncEngine.*` 提供网络、状态和独立启停。`MonitorSyncPage.*` 提供运行概览、设备应用状态、提交历史、目录打开、备份、迁移和端口设置。默认路径 `~/MachomeHubData/monitor-sync`，迁移后在配置指定的 state_file 保存新根路径/端口；失败保留旧数据，监听端口失败回到旧端口。当前部署配置的 state_file 位于用户 Application Support/MachomeHub/config。

客户端先比较服务器 epoch、日期版本和 TEMP 版本，服务器串行提交。缺失历史依赖可与当前日期一起提交，下载固定一次 HEAD。只有发布完成才 ACK；超时通过操作编号查结果。禁止输入任意路径和向生产成交文件写入。首版历史保留，不自动清理。
