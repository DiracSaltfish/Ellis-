| 09:35 硬截止 | 单纯刷新 FX 的间隔会留下缓存窗口 | 每次发布重新读墙钟并校验；后端计算和缓存读取再次校验，过期清空当前估值 | 09:14、09:15、09:34、09:35、10:00 边界；缓存读取到期测试 |
| 币对互相阻塞 | USD/HKD/EUR/100JPY 必须整组有效 | 缺失、倒挂、重复只影响对应币对；JPY 有效时不受缺失 USD 影响 | Go 部分币对、重复币对测试 |

| 正常即期恢复 | 早盘失败后按固定较长间隔查询 | 等待/回退时约 10 秒查询站内共享接口，成功后回到 60 秒；上游 CFETS 仍由共享服务每 2 分钟轮询 | Python 状态门控、Go realtime 切换测试 |
| 页面文案与状态 | 即期汇率固定写成小时参考价 | 区分即期 BID/ASK 中间价、前一有效交易日回退；显式显示预开盘禁止执行和输入失效 | Vue/TypeScript 生产构建 |
| 包内网站地址 | 指数上传器读 `NNN_PRIVATE_SERVER`，可能忽略四合一的 `NNN_SERVER_URL` | Supervisor 默认将私有上传网站地址设为组件配置地址，保留显式覆盖能力 | Supervisor 配置测试 |
| 任务中 native bridge socket 缺失 | 需要确认四合一是否仍依赖旧目录 socket | 包内指数上传器的 `NQMarket.connect()` 使用随包 `ib_insync` 直连配置的 TWS；没有该旧 native bridge socket 路径依赖 | 源码检查、冻结组件隔离检查；未连接真实 TWS |

“PCF 前交易日”可能早于最近 CFETS 交易日，例如海外 NAV 日期滞后，因此不强制两者完全相等；FX 只能取共享服务保留的同币对最后健康值，且不得早于 PCF 前交易日。没有使用固定“上周五”或固定 7 天窗口猜交易日。没有任何有效缓存时继续关闭估值，不编造 FX。

预开盘回退始终 `actionable=false`。油气 XOP、中概篮子、印度和白银不启用该回退。正常即期的原有业务与历史 `HistoricalBidAsk` 回放保留；本次没有把参考任务较老工作区整体覆盖进四合一，系数缓存、失败重试、上传 ACK、港股通中间价和收盘恢复逻辑仍在。

## 使用边界

1. 这些结果证明本次缺陷的本地代码修复与回归通过，不代表真实生产接管验收。没有测试当日真实 CFETS、真实 TWS 权限、生产 MySQL 或现场网络。
2. 单独替换上传端不足以实现完整能力：上述字段、回退校验和页面状态也需要配套网站后端/前端。本次这些改动都在四合一包内网站源码及产物中；dmit 现有网站没有被本任务修改。
3. 若四合一将来仍连接外部网站，该网站必须支持这里的 `source_observed_at` / `fallback_reason` 契约；否则不能把本地包验收当成端到端上线通过。
4. `NNN_PRIVATE_INDEX_PREOPEN_FX_FALLBACK` 可关闭预开盘回退；默认启用。缺少当日 PCF、可靠 prior FX 缓存或新鲜 Live 期货时仍不出回退估值。
5. 原有四合一长期稳定性、生产迁移和 Agent 崩溃隔离门槛仍见 9 月 5 日验收报告，本次没有宣称它们已消失。
