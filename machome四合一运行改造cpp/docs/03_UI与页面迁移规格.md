# 03 UI、四个子页与二级页面迁移规格

## 1. 整体框架

建议使用 Qt 6 Widgets，主窗口默认 1440×900，可缩至 1180×720：

```text
┌ 左侧导航 ┬──────────────────────────────────────────────────────┐
│ 总览     │ Machome / 当前时段 / 最后刷新 / 告警 / 维护模式      │
│ Upload   ├──────────────────────┬───────────────────────────────┤
│ 溢价率   │ 模块卡 1             │ 模块卡 2                      │
│ Webull   │ 状态+新鲜度+主动作   │ 状态+新鲜度+主动作            │
│ 实时申赎 ├──────────────────────┼───────────────────────────────┤
│          │ 模块卡 3             │ 模块卡 4                      │
│          ├──────────────────────┴───────────────────────────────┤
│          │ 最近异常 / 控制审计 / 调度时间线                     │
└──────────┴──────────────────────────────────────────────────────┘
```

左侧仅五个主入口：首页 + 四个模块。全局设置、构建信息、审计日志放在窗口工具栏/抽屉，不抢占主导航。

## 2. 首页

### 2.1 顶栏

- 主机名、IP/连接方式、OS/arm64、运行时长；
- 北京时间、当前交易阶段、日历来源；
- Hub Agent 连接状态和最后状态序列；
- 未确认告警数；
- 维护模式入口。

### 2.2 四张模块卡

每张卡固定显示：

1. 模块名与 `lifecycle + work_state`，同时使用文字/图标/颜色；
2. desired vs observed；
3. 上游状态；
4. 最近业务数据时间与 age；
5. 一个最有意义的业务量；
6. 下游连接数；
7. 最近错误或“按计划空闲”的解释；
8. 构建 ID/config hash 是否可证明；
9. 主动作和“查看详情”。

模块特有摘要：

| 模块 | 首页核心字段 |
|---|---|
| Upload | 网站/API、健康 uploader 数/总数、最近 ACK、最旧 heartbeat、30 秒 stale 数、失败/重试、日终任务 |
| 溢价率 | console/core/TGW、市场 phase、TGW session、ready/watch/hot/upstream、gap/drop/quarantine、信号、8421/19195 客户 |
| Webull | service/API、collector、auth、data state/age、sequence、source interval、gateway latency、client count |
| 实时申赎 | server、Wind 状态、monitoring、7 个标的 ready 数、最新 frame、6787 clients、PCF 当日/旧缓存/失败、QMT 状态 |

### 2.3 首页控制

- 正常态优先显示业务级 `暂停/恢复/自动`，而不是直接停进程。
- 服务级启动、停止、重启进入确认框，列出精确对象、依赖、影响和回滚。
- capability 未实现时按钮禁用，并显示原因，例如 Webull 目前外部 API 只读。
- 每张卡同时只允许一个未完成命令；显示阶段、耗时、取消是否可用和最终状态。
- 不提供无保护的“全部停止”。

## 3. 页面与路由模型

所有页面通过稳定 route ID 注册，而不是在主窗口硬编码索引：

```text
home
upload.overview
upload.web.route/{path}
premium.alert.detail/{signal_id}
premium.history
webull.book/{symbol}
webull.client/{client_id}
redemption.pcf/{trade_date}/{symbol}
redemption.history
```

`PageRouter::open(route, context, presentation)` 支持：

- `stack`：主内容区切页；
- `tab`：模块内页签；
- `window`：可并存非模态二级窗口；
- `external`：打开旧 app 或外部浏览器；
- `legacy_web`：可选 QWebEngine 深链。

每个二级窗口记录 route/context，可恢复窗口位置；模块重连时窗口保留并显示 stale/重连，不自动关闭。严禁使用会阻断整个主窗口的 `QDialog::exec()`；详情改为非模态 `show()` 或 dock/tab。

## 4. Upload 子页

### 4.1 页面结构

1. **服务总览**：Web 进程、8080、Git/build、磁盘、最近同步；
2. **上传器矩阵**：每个 launchd label 一行，显示 PID、desired/observed、stage、heartbeat、last success/failure、accepted symbols、重试；
3. **任务时间线**：盘中上传、日终份额、估值/锚点、历史回填；
4. **网站**：默认“在浏览器打开”，可选 QWebEngine 嵌入；
5. **日志**：按子进程、级别、游标增量查看。

### 4.2 原功能保留

首期不重写 Vue SPA，保留全部深链和浏览器前进/后退：

- 主页与分支；
- 基金详情 `/funds/{symbol}`；
- 有效仓位历史与份额历史三级页；
- 昨日赎回榜；
- debug、访问统计、NAV settings；
- 指南、留言。

若嵌入 QWebEngine，必须采用独立 profile、限制导航域和下载，并提供“外部浏览器打开”回退。Web 页面崩溃由 QtWebEngine 子进程隔离，不能影响 Hub Agent。

## 5. 溢价率子页

### 5.1 A 端五页原样平移

1. 实时拉升告警；
2. 历史信号审计；
3. 观察标的管理；
4. 额外 L1 行情维护标的；
5. 运行日志。

实时与历史信号继续打开完整触发详情，但改为非模态。历史加载/筛选/CSV 导出在 worker 执行，分页 model 或 virtual view 展示；禁止 UI 线程构造 50,000 行完整缓冲和全列 `ResizeToContents`。

### 5.2 A/B 边界

四合一是 machome 服务端控制台，默认只内嵌 A 端页面。B 端交易客户端继续独立：

- 信号列表、全局列表；
- 最多 4 个详情；
- 盘口、QMT1/QMT2；
- 申购、赎回、限价卖出、撤单。

Hub 可显示 B 客户连接与深链/启动入口，但不得让 A-core 接收交易指令。若未来希望同窗展示 B 页面，应使用独立权限域和明确“交易客户端”工作区，不与运维控制混在同一个动作栏。

### 5.3 首期复用

- 通过 8421 接 summary/status/detail；
- 19195 仅 status/ping 兼容验证，不新增订阅；
- “打开旧 A-console”保留为回退；
- 在 UI 源码尚未抽成库前，不做跨进程窗口嵌入。

## 6. Webull 子页

现有四个 tab 完整保留：

1. **实时盘口**：至少旧 UI 的 10 档，字段与颜色一致；显示 symbol、session、sequence、captured/published、interval、latency、changed；盘外缓存加醒目的 `STALE`，不能因 `/book` 返回 200 就误判 ready。
2. **客户端**：ID、remote、连接时间、最后发送、消息数。
3. **运行与登录**：auto/force running/force stopped、调度、登录监控、立即启动/停止、重启浏览器、打开登录窗、路径和 token 操作。
4. **日志**：增量 model、级别筛选、暂停滚动、复制脱敏行。

首页和详情都必须同时区分：

- API/service alive；
- collector active；
- auth state；
- data ready/fresh；
- cached snapshot 是否存在。

首期 C++ page 直接复用 `/v2/status`、`/v2/clients`、`/v2/stream` 及已有 Qt client。Python 旧面板继续可以打开。控制面协议完成前，内部 collector 控制保持禁用，不能通过停止整个 KeepAlive 进程模拟“停止采集”。

## 7. 实时申赎子页

### 7.1 主页面

- 主机服务/Wind/订阅/PCF/QMT 状态条；
- 保留 13 列主表：标的、名称、状态、买/卖/净份额、买/卖/净篮子、可申购篮子、机会、时间、最近变化；
- 行高亮、声音/弹窗冷却与当前逻辑一致；
- 双击行打开 PCF route。

### 7.2 二级能力

- PCF 详情：清单摘要、成分证券、QMT1、QMT2 四 tab；
- QMT 资金、当日委托、双击才提交申购/赎回 1 篮子；
- 变化历史：日期 + 标的过滤及原 8 列；
- 客户端设置：服务器、重连、心跳、弹窗、声音、重复、音量、冷却；
- 主机服务日志；
- 只读 Web 监控；
- 隐藏/恢复与托盘行为。

Wind 控制显示完整状态机：stopped/running/ready/warming/subscribing/monitoring/stopping/quitting/cleaning/error。busy 时禁用互斥按钮，明确显示正在执行的安全步骤。绝不提供“强杀 Wind”快捷按钮。

## 8. 日志与告警中心

模块页显示本模块日志；首页底部显示跨模块最近事件。日志读取要求：

- inode + offset 游标，轮转检测；
- 每次批量追加，不 `setPlainText(all)`；
- 每模块最多 N 行 ring buffer，达到上限丢旧并显示计数；
- token/cookie/account/password/URL query 脱敏；
- 日志来源、进程、timestamp、level、event key 可过滤；
- 原始业务日志只读，不改变原文件。

告警需要可解释：例如“Webull 按计划空闲”不报警；“交易时段数据 age > 阈值”才报警。通知失败只让 notification component 降级，不把行情误报为整体宕机。

## 9. 可访问性与误操作防护

- 状态不只靠颜色；始终有文本和图标。
- 所有可点击行支持键盘；主动作目标尺寸不少于 40×32。
- 交易/生命周期动作与普通导航视觉分离。
- start/stop/restart 的确认框显示 module ID、instance ID、build、当前 phase 和影响。
- 旧数据加时间戳与 stale 水印；禁止把 heartbeat 时间当行情时间。
- 发生控制超时后不允许立即重复未知动作，先查询原 `command_id`。
