## 1. 分析对象与方法

| 对象 | 类型 | 方法 |
|---|---|---|
| `tgw-1.0.9.2-py3-none-any.whl` (70MB) | Python 源码 + 原生库打包 | 直接解包（`unzip`），Python 层为**明文源码**，无需反编译 |
| `AmazingData-1.1.9-cp312-none-any.whl` | 纯 `.pyc`（Python 3.12 字节码） | 自建 pycdc（Decompyle++）批量反编译，59/59 成功产出 |
| `libtgw_python312.so` (8.9MB, ELF x86-64, stripped) | SWIG 原生扩展 | `nm -D` 导出符号表 + `strings` 静态特征分析 |
| `tgw.dll` / `_tgw.pyd` (Windows) | 同源 Windows 构建 | 结构与 Linux 版一致（同一 SWIG 工程） |
| TGW-SDK C++ 头文件 (2686 行) | **官方公开接口契约** | 作为 API 兼容重建的权威依据 |

工具链：`pycdc`(源码构建) / `radare2` / `nm` / `strings` / `cmake+clang`。

### 2.1 关键证据

1. **SWIG 生成痕迹**：`tgw.py` 头部注释 `automatically generated by SWIG`；
   符号表含 `SwigDirector_*`、`swig_traits_info<galaxy::tgw::SecurityInfo>` 等。
2. **静态链接 CPython**：导出表含全部 `Py*` 运行时符号（`PyInit__io`、`PyArg_Parse`…1667 个），
   解释了为何单个 so 达 8.9MB。
3. **完整 C++ 类结构**（从 mangled symbols 恢复）：
   - SPI 接口：`IGMDSpi, IGMDHistorySpi, IGMDKlineSpi, IGMDCodeTableSpi, IGMDExFactorSpi,
     IGMDFactorSpi, IGMDThirdInfoSpi, IGMDSecuritiesInfoSpi, IGMDETFInfoSpi,
     IGMDSnapshotSpi, IGMDTickOrderSpi, IGMDTickExecutionSpi, IGMDOrderQueueSpi`
   - 数据结构：`MDSnapshotL1/L2, MDIndexSnapshot, MDOptionSnapshot, MDHKTSnapshot,
     MDFutureSnapshot, MDKLine, MDTickOrder, MDTickExecution, MDOrderQueue,
     LogonResponse, RspQueryStatus, RspTaskStatus, SecurityInfo ...`
   - 与官方头文件 `tgw.h / tgw_struct.h` 一一对应 → 头文件即权威 API 契约。
4. **API 入口全集**（字符串表）：`IGMDApi_Init(spi, cfg, api_mode:uint16, path:string)`、
   `Login→Init` 封装、`Query{Kline,Snapshot,CodeTable,SecuritiesInfo,ETFInfo,Factor,HQFactor,
   ExFactorTable,ThirdInfo,TickOrder,TickExecution,OrderQueue}`、`Subscribe/UnSubscribe/
   SubFactor/ReplayRequest/CancelTask/UpdatePassWord/GetTaskID/GetVersion/Release`。

## 3. Python 层行为还原要点（反编译交叉核对）

### 3.1 tgw_login（AmazingData 登录流程）
- 校验用户名必须 `tgw_` 前缀（反编译显示条件被优化器反转，语义以手册为准：非法前缀抛
  `username is illegal`）。注意：**C++ 层无此校验**，纯 Python 层行为。
- 流程：`Close()` → 注入日志 SPI → 组装 `Cfg{username,password,server_vip,server_port,force_logout}`
  → `api_mode` 映射（kInternetMode=2 / kColocationMode=1）→ `Login(cfg, mode)`。
- 失败重试：若日志 SPI 报告 `max_limitation`（同账号顶号上限），强制带 `force_logout=True`
  重试最多 5 次、间隔 2s；仍失败则打印 `login fail` 并 **exit(0) 杀进程** —— 桥接服务必须绕开此路径。

### 3.2 BaseData.get_calendar 的真实实现（反编译还原）
```python
task_id = tgw.GetTaskID()
tgw.SetThirdInfoParam(task_id, 'function_id', 'A010061003')
tgw.SetThirdInfoParam(task_id, 'start_date', '19900101')
tgw.SetThirdInfoParam(task_id, 'end_date', str(date))
tgw.SetThirdInfoParam(task_id, 'market', {'SH':'SSE','SZ':'SZSE','BJ':'NEEQ',
    'SHF':'SHFE','CFE':'CFFEX','DCE':'DCE','CZC':'CZCE','INE':'INE',
    'SHN':'SHHK','SZN':'SZHK'}[market])
trade_days_df, _ = tgw.QueryThirdInfo(task_id)
# 北交所日历从 20211115 起有效；结果按升序写入 self.calendar
```
→ 揭示了「三方资讯查询」通道的通用模式：`function_id + 参数字典 + QueryThirdInfo`，
这是 InfoData 全部 ~45 个接口的底层机制。

### 3.3 并发与缓存常量（environment.py 还原）
- 全局 `RLock` 保护查询；每类接口有分页步长（如 kline=500/次、snapshot=50/次、
  财务类=200/次、复权因子=300/次），循环拉取直到取空。
- 重试次数默认 3。

### 3.4 反编译质量评估
- 类骨架/方法签名/常量表/docstring：**100% 还原**
- 控制流：~85% 可读（Python 3.12 新 opcode `POP_JUMP_IF_NOT_NONE`、`LOAD_FAST_AND_CLEAR`、
  `MAKE_CELL` 有缺口，pycdc 输出中留有 `WARNING: Decompyle incomplete` 标记）
- 结论：足以支撑行为级伪源码重建，无需逐字节等价。

## 4. 原生层（libtgw 核心）逆向边界 —— 重要

原生核心承担：TLS(证书 `.ca.crt`)、私有二进制协议帧、心跳/重连、订阅路由、protobuf 风格序列化。
该部分 **stripped 无符号**，且为静态链入，完全还原需数周级人工反汇编（IDA/Ghidra 逐函数），
不属于本次会话可行范围。本次采取：

1. **API 兼容骨架**：按公开头文件 1:1 实现 `galaxy::tgw` 接口面（原创实现代码）；
2. **协议接缝（Protocol Seam）**：所有线上字节流收口到 `ITransport` 虚接口，
   macOS 版默认提供 `LoopbackTransport`（本地回环/模拟数据）——结构上已为后续深度协议
   逆向或对接自建网关留好位置；
3. **诚实预期**：骨架能完成 Init/Login 状态机与回调分发逻辑并编译成 arm64 dylib，
   但**不包含厂商私有线上协议**，直接对银河生产服务器登录预计止步于 TLS/协议握手层
   （见 §7 实测记录）。
