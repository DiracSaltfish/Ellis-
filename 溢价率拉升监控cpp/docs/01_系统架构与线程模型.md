# 01｜系统架构与线程模型

```text
TGW WSS → etf-premium-tgw(C++20) → UDS/Protobuf → A-core(C++20)
                                                        ├─ 4 个 symbol 哈希分片
                                                        ├─ 独立落盘线程
                                                        ├─ 8421 summary/detail
                                                        └─ 19195 L1 v1
                                                               ↓
                                                     B(Qt6 macOS/Windows) → QMT1/QMT2
```

## 进程边界

- `A-console`：GUI 监管器，启停/重启 core/adapter，通过 8421 显示阶段、就绪数、SDK/计算/落盘队列、隔离帧和快照。关窗进托盘；明确退出才停子进程。5 分钟最多自动重启 3 次，然后 `FAULT`。
- `etf-premium-tgw`：原生 C++ TGW 登录、TLS/WSS、鉴权、订阅/退订、Zstandard 解压、原始类型门禁和转发。不计算溢价，不依赖 Python TGW wheel。
- `A-core`：full/delta 合并、严格类型和缩放检查、信号、留存和主推。
- `B`：显示/提醒/本地已读和人工交易；A 不接收、代理或审计交易指令。

## adapter 执行模型

TGW/仿真工作线程在入队时记 wall/monotonic ns；Qt 主线程按序写 UDS 并处理 `set_symbols/quotes_desired`。事件队列上限 10,000。队列或 UDS 写缓冲越界时不继续使用残缺 delta 链，而是断开桥、清队列、关闭 TGW 会话，重连后重新登录/订阅并等待 full。

桥接重连改变 `bridge_epoch`：仿真重发 full；真实路径关闭 TGW、新 session 登录并重订阅，保证 A 不把新 delta 接旧状态。原始服务器 JSON 字节不经反序列化重写后再转发，避免 Python 对象自动类型转换改变证据。

## A-core 线程

router 用 `qHash(symbol)%4`使同证券始终进同一 `QuoteWorker`。每 worker 独占 `SnapshotParser+SignalEngine`，为单写者。每分片最多 4,096 帧；溢出则累计 `worker_drops`、严重告警并使整分片重新等 full，避免在丢 delta 后继续计算伪状态。

raw/normalized/signal 投递到独立 `PersistenceWriter` 线程，上限 10,000。落盘队列满或剩余空间低于 5 GiB 时停历史行情写入且告警，不阻塞计算/推送。

## 网络隔离

B 仅保持一条 summary 和一条共享 detail 连接，详情流量/重连不阻塞信号。8421 和 19195 任一客户待写超 1 MiB 即只断开该 `slow_client`。数据通道只包含快照/信号，QMT 凭据和指令不进 A。

## 关键故障语义

| 故障 | 结果 |
| --- | --- |
| adapter 断开/session 变更/adapter_seq 缺口 | 清 A 缓存/窗口与 19195 ready，每标的等 full |
| delta-before-full/身份缺失 | raw 留存，不标准化/发布/计算 |
| 数字类型/档位异常 | 质量位 + 隔离 |
| B 离线 | A 持续；重连补发 30 分钟 |
| QMT 结果未知 | 同标的同方向锁 10 秒，查委托，不自动重发 |
