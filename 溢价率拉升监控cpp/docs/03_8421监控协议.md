# 03｜8421 监控协议

## 连接与限额

- `ws://A:8421/ws/v2/summary`：主表、信号、质量和运维状态。
- `ws://A:8421/ws/v2/detail`：详情兴趣、缓存十档与后续主推。
- 两类各最多 256 连接；每个 B 一条 summary + 一条共享 detail，detail 最多 4 symbol。
- `0.0.0.0`、明文、无认证，仅可信内网。

## summary 同步

连接后 A 自动发送一次 `sync_begin`→当前 `summary(backfill=true)`→最近 30 分钟 `signal(backfill=true)`→`sync_complete`；也可人工发 `{"op":"sync"}` 重取。B 不再在 connected 回调重复发 sync，避免同一批 202 标的重复同步。B 在 complete 前或 backfill 帧不发声，只对之后实时信号鸣笛/系统通知。

`summary` 含 `s/name/market/orig_time/receive_wall_ns/publish_wall_ns`、`last_price_e6/bid1_price_e6/iopv_e6`、`change_ppm/sell_premium_ppm/display_premium_ppm`、`bid_rise_150s_ppm/bid_rise_300s_ppm`、雷达指标 `bid_rise_30s_ppm/bid_rise_60s_ppm/bid_rise_90s_ppm/momentum_3m_ppm/momentum_5m_ppm/adaptive_3m_ppm/adaptive_5m_ppm/minute_range_ppm/minute_range_base_ppm`、`iopv_static/source_ready/replay`、`mapping_verified/mapping_version/quality`。

`signal` 含 `signal_seq/symbol/name/occurred_at/model/premium_ppm/rise_30s_ppm/rise_300s_ppm/bid_rise_150s_ppm/bid_rise_300s_ppm` 以及与 summary 同名的雷达指标、`reason/repeat/replay/backfill`。`model` 是按 `premium`、`pull`、`radar` 固定顺序用 `+` 拼接的当帧实际告警模型，例如 `radar`、`premium+radar` 或 `premium+pull+radar`；消费者不得假定只有旧的三个枚举值。新产生的信号还携带触发时刻审计字段：`last_price_e6/bid1_price_e6/iopv_e6/orig_time/source_session/receive_wall_ns/publish_wall_ns/iopv_static/mapping_verified/mapping_version/quality`。旧历史记录允许缺少这些追加字段，消费者必须显示缺失，不能用当前行情回填为历史值。

A-console 与 B 使用同一条 summary 信号流、同一 `signal_seq` 和同一 A-core 判定结果。两端都只对 `backfill=false && replay=false` 的新实时信号发声；连接补发和回放记录只进入显示/审计。

A 每 5 秒发 `status`：adapter 会话/序号缺口、SDK 队列、4 分片当前/峰值/丢弃、核心当前/最大延迟、落盘队列/停写、可用磁盘、就绪数、客户数、慢客户端丢弃、时段和 simulation/replay。A-console 还可发 `{"op":"raw_snapshot"}`，A 只向请求连接返回最近一条带会话、序号、接收时间、full/delta、tag 和原始事件的 `raw_snapshot`。

summary/detail 每个 WebSocket 待写超过 1 MiB 即只断开该慢连接；两类连接和发送路径彼此独立。

## A-console 观察清单管理

仅 loopback summary 连接可发：

```json
{"op":"set_watchlist","symbols":["159866.SZ","513100.SH","164824.SZ"]}
```

A 严格校验唯一 `^[0-9]{6}\.(SH|SZ)$`、1–1000 个标的，原子写回 `watchlist.json`，再更新上游引用集合。回复 `watchlist_ack`；移除时向所有 B 发 `symbol_removed`，清该标的解析/信号状态并精确退订。非 loopback 调用拒绝，防止可信内网中的普通 B 改生产清单。

## detail

```json
{"op":"subscribe","symbol":"159518.SZ"}
{"op":"unsubscribe","symbol":"159518.SZ"}
```

成功先返 `detail_ack`。有缓存则立即返 `detail,cached=true`；之后每次 TGW 新快照立即主推 `cached=false`，没有 3 秒轮询。当前 A 观察清单内标的只增下游兴趣，不重复订阅 TGW；关闭详情/B 断线即删兴趣。

detail 除 summary 字段外含 pre-close/open/high/low/high-limit/low-limit、买卖十档 e6/e2、累计量 e2、金额 e5、成交笔数和 phase。

## 版本规则

v2 只可追加可选字段；改单位/删字段必须升主版本。价格和比率在协议中保留定点整数，避免 JSON 浮点二次缩放。
