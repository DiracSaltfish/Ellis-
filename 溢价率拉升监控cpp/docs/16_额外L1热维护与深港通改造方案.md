# 额外 L1 热维护与深港通改造方案

> 状态：`IMPLEMENTED_RELEASE_CANDIDATE_PENDING_MACHOME_ACCEPTANCE`
>
> 本文是基于 2026-08-27 代码库影响分析和 `02800` 深股通实测形成的实施方案。方案已于当日进入代码与离线测试；是否可投入生产以 `docs/18_20260827_额外L1热维护与深港通实施验收.md` 和最终上线意见为准。

## 1. 已确认的产品约束

1. A 端“观察标的管理”和“额外 L1 行情维护标的”是两个同级顶层选项卡。顺序固定为：
   `实时拉升告警 | 历史信号审计 | 观察标的管理 | 额外L1行情维护标的 | 运行日志`。
2. 观察标的：参与行情订阅、溢价率/价格拉升计算、A 端告警、A→B 推送和既有市场数据留存。
3. 额外 L1 热维护标的：仅用于提前建立上游行情、保留必要的最新快照内存缓存，并向实际订阅它的 19195 客户端实时转发；不进入 SignalEngine，不进入 A/B 告警和 B 的全局/信号列表，不写入原始行情或标准化行情持久化文件。
4. 观察列表与热维护列表允许包含同一证券。角色在上游按证券合并，只存在一个订阅流；观察角色优先决定计算、告警、B 推送和留存资格。
5. 港股只走深港通路由，不实现沪港通，也不在深港通失败后回退沪港通。
6. 港股代码只接受五位代码加 `.HK`，例如 `02800.HK`。不接受 `2800.HK`，不自动补零；配置、内存键、19195 请求和输出均使用同一规范形式。
7. 沪深订阅时段为周一至周五 09:15:00–15:00:00；深港通订阅时段为周一至周五 09:30:00–16:00:00。午间维持订阅，不反复退订、重订。
8. 仍只按周一至周五判断，不接入交易所节假日日历。
9. 订阅失败必须退避，单个坏证券或单批失败不能形成紧密重试，也不能阻塞其他证券。
10. 19195 的既有 NDJSON v1 结构不变；原 CPPUI 继续只请求 `.SH/.SZ`，无需感知 `.HK`。

## 2. 现状与改动边界

### 2.1 当前关键限制

- `CoreServer::loadWatchlist` 和 `CoreServer::replaceWatchlist` 只接受六位 `.SH/.SZ`，并用一个 `fixedSymbols_` 同时表达订阅、监控、推送和留存资格。
- `LegacyL1Server` 将默认观察标的与动态订阅混在一套 `maintainedSymbols` 中，存在 60 秒动态引用释放机制，但没有独立的热维护角色。
- A→adapter 只有一份 `set_symbols` 目标集合和一个全局 `quotes_desired` 开关。
- adapter 将非 `.SH` 证券全部当作深圳普通快照；现状无法正确构造港股通 `kHKTSnapshot`。
- `SnapshotParser::mapSnapshot` 只实现沪深普通快照；深港通 tag 16 的数字键布局不同。
- `QuoteWorker` 对所有成功解析的快照运行 SignalEngine，必须在工作线程入口处增加角色门控。
- Console 目前先保存文件再请求 Core 应用，Core 拒绝时可能出现“文件已保存、运行态未应用”的分裂状态。

### 2.2 本次不做的事项

- 不给 B 增加港股列表、港股详情或港股交易能力。
- 不改变 QMT 交易协议，不把 `.HK` 引入现有交易代码的通用 `normalizeSymbol`。
- 不改变 19195 的消息类型、必填字段或沪深字段语义。
- 不自动为港股补零，不进行证券代码猜测。
- 不留存热维护标的的逐笔原始帧或标准化快照。
- 不引入沪港通备用路由。

## 3. 目标角色模型

每个规范证券键维护独立角色位：

| 角色 | 来源 | 固定订阅 | 信号计算 | A→B | 19195 | 行情文件留存 |
|---|---|---:|---:|---:|---:|---:|
| `MONITORED` | 观察标的列表 | 是 | 是 | 是 | 按客户端请求 | 是 |
| `HOT_L1` | 额外 L1 热维护列表 | 是 | 否 | 否 | 按客户端请求 | 否 |
| `DYNAMIC_L1` | 19195 客户端请求 | 引用存在时 | 否 | 否 | 是 | 仅既有容量验收策略允许时 |

角色合并规则：

1. 上游目标集合是三类角色的并集，并按规范证券键去重。
2. `MONITORED + HOT_L1` 只产生一次 Subscribe；移除任一角色但仍有另一角色时不退订。
3. `MONITORED` 被移除但 `HOT_L1` 或 `DYNAMIC_L1` 仍存在时，只停止信号计算、B 推送和行情留存，保留解析状态、最新快照和上游订阅。
4. 证券最后一个角色消失且动态订阅 60 秒宽限期结束后，才从上游目标集合移除，并清除该证券 parser/full 状态和可淘汰缓存。
5. 由非观察角色升级为 `MONITORED` 时，清空该证券 SignalEngine 窗口并按当前交易时段重新预热，禁止用热维护期间的旧窗口立即触发信号。
6. 所有异步队列项携带 `role_generation`；工作结果发布前再次检查当前角色代次，防止移除观察角色后队列中旧任务泄漏信号或 B 推送。

## 4. 证券规范与路由

### 4.1 独立的行情证券规范器

不得修改交易链路共用的通用证券规范函数。新增仅供市场数据使用的严格规范器：

- 沪市：`^[0-9]{6}\.SH$`
- 深市：`^[0-9]{6}\.SZ$`
- 深港通：`^[0-9]{5}\.HK$`
- 后缀统一转为大写；数字部分不变。
- `2800.HK`、`0002800.HK`、`02800.SZ`、空代码和带空格代码均明确拒绝，并返回可显示的错误原因。

### 4.2 adapter 订阅映射

| 规范证券 | SDK code | SDK market | public_flag | 用途 |
|---|---|---:|---:|---|
| `513520.SH` | `513520` | `kSSE` | `kSnapshot` | 沪市 L1 |
| `159518.SZ` | `159518` | `kSZSE` | `kSnapshot` | 深市 L1 |
| `02800.HK` | `02800` | `kSZSE` (102) | `kHKTSnapshot` (12) | 深港通 L1 |

`.HK` 路由为固定实现：`kSZSE + kHKTSnapshot`。若 Subscribe 明确失败，只记录并退避；不得转换为 `kSSE` 重试。

## 5. 深港通快照解析

adapter 继续保持原始事件类型和数字键，不在 Python 中缩放或重排。C++ 根据 `tag == 16` 分派到独立的 `mapHktSnapshot`：

| 数字键 | MDHKTSnapshot 字段 | 核心单位/处理 |
|---:|---|---|
| 1 | market | 必须为 102；同时记录业务市场 `HK` 和路由 `SZ_CONNECT` |
| 2 | code | 必须为五位数字，规范为 `.HK` |
| 3 | orig_time | 原始整数时间戳 |
| 4 | trading_phase_code | 保留原始字符串，包括尾部 NUL 的清理后显示值 |
| 5 | total_volume | 原始整数，数量比例 `1e2` |
| 6 | total_amount | 原始整数，金额比例 `1e5` |
| 7 | pre_close_price | 价格比例 `1e6` |
| 8 | nominal_price | 价格比例 `1e6`，单独保留 |
| 9 | high_price | 价格比例 `1e6` |
| 10 | low_price | 价格比例 `1e6` |
| 11 | last_price | 价格比例 `1e6`，19195 的 `lp` 来源 |
| 12 | bid_price[5] | `|` 分隔的五档定点整数 |
| 13 | bid_volume[5] | `|` 分隔的五档数量整数 |
| 14 | offer_price[5] | `|` 分隔的五档定点整数 |
| 15 | offer_volume[5] | `|` 分隔的五档数量整数 |
| 16–22 | 参考价、涨跌停和盘口限制 | 保留标准化字段和质量检查，不扩展 v1 |
| 23 | variety_category | 严格整数 |

解析规则：

- 状态键必须包含 `(session_id, canonical_symbol, tag)`，防止不同源或重连状态串写。
- full 建立完整状态；full 之后 delta 才允许合并；重连后旧状态全部失效，必须重新收到 full。
- 重复 full 是合法行为，应整体替换旧状态。
- 价格、数量和金额保持整数与显式比例；只在 19195/UI 边界格式化，禁止用二进制浮点作为状态主值。
- 港股通快照没有可可靠映射的开盘价字段。为保持 v1 结构，`o` 输出 `0`，不得拿 nominal 或其他字段冒充开盘价。
- 港股只向 19195 输出前五档，保持既有 `books` 结构。
- 类型错误、数组档数错误、负数、买卖价次序异常和时间倒退分别设置质量位；严重结构错误隔离该帧，不污染上一次有效快照。
- 修正 `CoreServer::symbolHint`：代码来自数字键 `2`，不能把键 `1` 的 market 当作代码；港股需结合 tag 规范为 `.HK`。

## 6. 订阅时段与“不反复退订”

Core 分别计算两个市场窗口，不改原信号时段状态机：

| 时间（工作日） | 沪深目标 | 深港通目标 | 信号行为 |
|---|---:|---:|---|
| 09:15–09:30 | 保持订阅 | 未启动 | 沪深仅采集，不告警 |
| 09:30–11:30 | 保持订阅 | 保持订阅 | 观察标的按既有预热/规则 |
| 11:30–13:00 | 保持订阅 | 保持订阅 | 不触发信号，绝不午间退订 |
| 13:00–14:57 | 保持订阅 | 保持订阅 | 观察标的按既有预热/规则 |
| 14:57–15:00 | 保持订阅 | 保持订阅 | 不触发信号 |
| 15:00–16:00 | 已移除 | 保持订阅 | 无沪深信号；港股只做 L1 |
| 其他时间 | 未订阅 | 未订阅 | 19195 仍监听，返回带原时间的缓存或 missing |

实现不需要扩展 Python→C++ 市场帧协议。Core 每次只发送“此刻应活跃的规范证券并集”：

- 15:00 从目标集合移除 `.SH/.SZ`，保留 `.HK`。
- 16:00 目标集合为空并令 `quotes_desired=false`。
- 午休前后目标集合不变，因此不会触发退订或重订。
- 盘外人工启动可显式强制两个市场组上线；真实信号仍受硬时段锁。

当某市场时段关闭导致证券从目标集合移除时，Core 清除该证券会话内 full 合并状态。下一次开窗必须等待新 full，不能把次日 delta 合并到前一交易日状态。

## 7. 订阅失败隔离与退避

### 7.1 分组和隔离

- 普通沪深快照与深港通快照分别组批，避免一个 HKT 错误拖累 202 个沪深标的。
- 批量 Subscribe 失败后对失败批次进行拆分定位，成功证券保持成功状态，不做全量反复重订。
- 每个证券维护 `desired / subscribing / subscribed / awaiting_full / ready / backoff / removed` 状态。
- Subscribe 返回成功后进入 `awaiting_full`；暂时没有行情不等于订阅失败，不能因“无 tick”循环 Subscribe。

### 7.2 退避参数

建议每证券使用带抖动的指数退避：`1, 2, 4, 8, 15, 30, 60, 120, 300` 秒，300 秒封顶。

- 仅在明确的订阅失败、连接断开或会话失效后重试。
- 同一证券重试计时独立，单个坏代码不能占满全局队列。
- 删除证券、重新添加证券或建立新 SDK 会话时重置其失败代次。
- 连接登录失败使用独立的会话级退避，也以 300 秒封顶。
- A-console 显示下一次重试时间、失败次数、最近错误和所属订阅批次。

## 8. A 端 UI 与配置事务

### 8.1 新顶层选项卡

“额外 L1 行情维护标的”页包含：

- 代码输入框。
- 市场选择：上海 SH、深圳 SZ、深港通 HK。
- 添加、移除选中按钮。
- 表格列：规范证券、市场/路由、名称、当前角色（显示是否与观察列表重叠）、上游订阅状态、full-ready、最近行情时间、19195 引用数、重试次数/最近错误。
- 汇总：热维护数量、与观察列表重叠数、当前活跃沪深/港股数量、唯一上游订阅数和剩余容量。

输入规则：SH/SZ 输入六位数字；HK 输入五位数字且必须保留前导零。保存和显示始终为 `02800.HK`。

### 8.2 Core 作为配置唯一提交者

新增 `l1_hotlist.json`，缺失时按空列表启动。为避免当前 Console“先写文件再请求 Core”造成分裂，改为：

1. Console 把候选完整列表发送给本机 Core。
2. Core 校验格式、唯一性、总容量、路由支持和当前角色并集。
3. Core 使用临时文件 + 原子替换持久化配置。
4. Core 更新角色代次、上游目标和状态，并回传规范化后的权威列表。
5. Console 只按 Core 的确认结果刷新表格。

旧 `set_watchlist` 操作保留兼容别名，但内部也走相同事务。配置损坏时明确进入配置错误状态，不静默丢弃条目。

容量按“唯一上游证券”计算，默认上限仍为 1000：固定观察和热维护角色优先占用；19195 动态请求只能使用剩余容量，超限按既有错误帧拒绝。

## 9. 计算、推送与留存门控

### 9.1 工作线程

解析与 L1 转发仍按证券哈希分片保持单证券有序。进入 SignalEngine 前读取不可变角色快照：

- `MONITORED`：解析、计算、A 告警、B 推送、19195 按需转发、留存。
- `HOT_L1`/`DYNAMIC_L1` 且非 `MONITORED`：解析与 19195 转发，完全绕过 SignalEngine。

发布阶段再次核对 `role_generation`，防止并发移除后的迟到信号。

### 9.2 明确的留存矩阵

| 当前角色组合 | 原始事件文件 | 标准化行情文件 | 信号/审计 | 运维日志 |
|---|---:|---:|---:|---:|
| `MONITORED`（含重叠） | 是 | 是 | 是 | 是 |
| 仅 `HOT_L1` | 否 | 否 | 否 | 是 |
| `HOT_L1 + DYNAMIC_L1`、无观察 | 否 | 否 | 否 | 是 |
| 仅 `DYNAMIC_L1` | 仅既有容量验收开关允许时 | 同左 | 否 | 是 |

热维护证券允许在内存中保留：最新完整快照、full/delta 合并状态、原始行情时间、接收时间、质量位、订阅状态和 19195 引用数。不得将这些行情写入日分区文件。订阅成功/失败、退避和人工配置变更属于运维审计，可以写日志。

为避免动态证券缓存永久增长，设置 `max_l1_cached_symbols`（建议 2000）和非固定动态缓存 TTL/LRU。观察/热维护证券为 pinned，不参与 LRU；仅动态角色消失后才可淘汰。

## 10. 19195 兼容设计

协议仍使用现有 NDJSON v1：

- subscribe 请求新增接受精确 `02800.HK`，但消息结构不变。
- hello、subscribe_ack、l1、status 和 error 的已有字段不删除、不改类型。
- 沪深 `l1` 序列化结果必须与改造前逐字段一致。
- 港股沿用五档 `books`；`lp` 使用 last price，`o=0`，原始行情时间照常写入 `rt`。
- 服务端只向某客户端推送其实际订阅的证券；热维护本身不会造成对所有 19195 客户端的广播。
- 已预热的 `02800.HK` 在 19195 首次 subscribe 时立即返回内存缓存；未预热则先返回 missing/ack，等待首个 full 后主动推送。
- 非港股交易时间接受 `.HK` 请求，但不启动上游；若返回缓存，必须保留原 `rt`，不得伪造为新鲜行情。

为最大化兼容性，`hello.defaults` 继续表示原观察列表；内部新增 pinned union 不直接改变该字段语义。状态响应可以增加可选汇总字段，但 CPPUI 不依赖它们。

## 11. B 端改造影响

B 端本次不增加用户可见功能，需保持以下隔离：

- 热维护标的不进入 B summary、信号列表、详情订阅或 30 分钟信号补发。
- `.HK` 不出现在 B；B 仍只处理观察标的的沪深 ETF 监控与现有 QMT 操作。
- A 增加的可选状态字段必须向后兼容，B 忽略未知字段。
- 观察标的降级为热维护标的时，A 向 B 发一次 `symbol_removed`；A 的 19195 快照与上游订阅继续存在。
- 热维护标的升级为观察标的时，必须先完成信号窗口预热，再允许 B 收到实时信号。

因此 B 生产代码原则上无需改协议；主要工作是增加回归测试，证明角色隔离和旧客户端兼容。

## 12. CPPUI 影响评估

对 `/Users/ellis/QMTUI/CPP/Web/UI_V26_溢价率订阅` 的分析结论：

1. 当前 `QmtL1QuoteAdapter` 把证券字符串大写、去重和排序，发送既有 v1 subscribe；没有把 `.SH/.SZ` 写死为唯一可解析后缀。
2. CPPUI 只请求沪深代码，服务端又按客户端订阅集合定向推送，因此新增 `.HK` 不会让它收到港股帧。
3. 19195 v1 的沪深消息结构和字段类型不变，所以无需修改 CPPUI 生产代码。
4. 保留并运行既有 multiwindow smoke：hello、订阅并集/去重、事件驱动、freshness、乱序保护、缓存重放、重连和 idle grace。
5. 港股使用独立的协议测试客户端验证，避免为了未使用的市场改动 CPPUI。

风险点是服务端若错误地把热维护行情广播给所有客户端，或改变 hello/defaults 语义，会影响 CPPUI；本方案通过按客户端订阅过滤和保持 defaults 语义消除该风险。
