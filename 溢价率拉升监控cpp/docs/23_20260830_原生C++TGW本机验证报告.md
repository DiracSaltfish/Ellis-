## 4. 数据类型加强审查结果

运行时和审计工具共用 `RawEventValidator + simdjson`，按 JSON token 的真实词法类型判断，
不使用 Python 自动转换，也不让数字先经过 `double`。`headers.tag`、证券代码、精确整数、
full/delta 字段集合和盘口编码均为 fail-closed；错误帧隔离，不进入状态合并。

### 4.1 已保存沪深实盘样本

对四份 `logs/live-validation/tgw-*-events-20260827.jsonl` 全量审计：

| 维度 | 结果 |
| --- | ---: |
| 总事件 / 严格通过 / 失败 | 6,593 / 6,593 / 0 |
| full / delta | 1,283 / 5,310 |
| 证券数 | 203 |
| tag 14 / tag 16 | 6,593 / 0 |
| numeric / named schema | 6,593 / 0 |
| 最大行 | 596 bytes |

全部 `tag` 和证券代码是 string，`status/is_delta/market/orig_time` 是精确 int64；盘口
12–15 在出现时均为 string 且恰好 10 项。`orig_time` 范围
`20260827102845000–20260827105025357`，累计成交额最大 `333515305600000`。

### 4.2 HKT 既有证据

现有证据只有 `02800` 的 6 条实盘事件（2 full / 4 delta，约 30 秒），因此证据强度低于
沪深。回归固定了五位字符串代码 `02800`、tag 16、market 102、五档字符串以及
`orig_time=20260827154936000`、`total_amount=1952183035644000`。这两个大整数均不允许
经过 IEEE-754 double。

### 4.3 历史压缩归档的新增发现

对 `data/raw-20260827.jsonl.zst` 流式解压审计，共 650,295 条旧版确定性仿真：

- 627,915 条位于 A-core 顶层 `event` 包裹，提取后原始 JSON bytes 不重序列化；
- 646,474 条 named-schema delta 符合当前合同；
- 3,821 条旧格式 full 缺少当前合同要求的 `variety_category`，被严格拒绝；
- 这些是旧仿真生成器格式，不是 TGW 服务端实盘坏包，也不应为了让历史统计变绿而放宽
  生产接收合同。

这个发现修正了“65 万条全部属于同一有效格式”的旧判断，也证明审计器能够把 Python/Qt
可能自动容忍的缺字段暴露出来。标准输入 EOF 的空行误计数在审计过程中被发现并修复，
最终行数与归档记录数一致。

## 5. 已覆盖风险与证据缺口

已用代码和回归固定的高风险项：证券代码前导零、17 位时间、15–16 位累计额、整数与
`0.0/1e3/string/bool` 的区别、未知键、缺字段 full、delta-before-full、断线后的 session
重置、队列溢出、删除证券后的排队旧事件、鉴权 token/密码不入日志。

仍未关闭的缺口：当前 TGW 服务端的盘中实际字段集合、HKT 更长窗口、首 full 与 delta
时序、批量订阅节流、断线重连、目标 machome 的 dylib/证书/签名环境，以及完整清单在高峰
流量下的容量。它们都需要周一真实行情，不能用周末仿真替代。
