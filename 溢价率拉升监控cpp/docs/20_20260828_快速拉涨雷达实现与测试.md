# 2026-08-28 快速拉涨雷达实现与测试

## 结论

版本 `0.3.1` 在原有 `premium`（溢价率突升）和 `pull`（150/300 秒买一拉涨）之外保留独立 `radar` 模型。三个模型为 OR；任何一个可以单独触发，同一帧同时命中只产生一个组合事件。`radar` 从 0.3.1 起统一要求 IOPV 有效且可卖溢价率严格大于 0.60%。

该版本已完成本地编译、单元测试、UI 测试、Python 适配层回归、严格编译警告检查和 AddressSanitizer/UndefinedBehaviorSanitizer 检查。2026-08-28 02:21 部署的是未加 0.60% 总门的 `0.3.0`；09:44 已用 `0.3.1` 替换 machome 的 A 端生产程序。随后发布的 `0.3.2` 仅改进 B 的信号列表和通知焦点行为，A-core 保持同一门控逻辑。新雷达仍需在真实 3 秒行情下统计 T30/T60/T90 的误报率。

## radar 分支

先决条件：`usable_IOPV && sellPremiumPpm > 6000`。这个门包围全部 M3/M5/A3/A5/RANGE_UP/T30/T60/T90；无 IOPV 标的仍可按原规则进入 `pull` 模型，但不再进入 `radar`。

| 代码 | 条件 | 数据 |
| --- | --- | --- |
| M3 | 当前最新价相对 3 分钟前收盘 ≥0.30% | 实时构造分钟线 |
| M5 | 当前最新价相对 5 分钟前收盘 ≥0.50% | 实时构造分钟线 |
| A3 | 相对前 3 个连续分钟收盘最低值 ≥max(0.15%, 2.5×历史中位数) | 最多 120 个本时段历史值 |
| A5 | 相对前 5 个连续分钟收盘最低值 ≥max(0.25%, 2.2×历史中位数) | 最多 120 个本时段历史值 |
| RANGE_UP | 当前分钟振幅 ≥max(0.15%, 2×历史中位数)，且当前价高于前一分钟收盘 | 当前分钟临时 OHLC |
| T30 | 完整 30 秒最低买一到当前买一 ≥0.15% | 最多 1Hz 的买一序列 |
| T60 | 完整 60 秒最低买一到当前买一 ≥0.20% | 最多 1Hz 的买一序列 |
| T90 | 完整 90 秒最低买一到当前买一 ≥0.25% | 最多 1Hz 的买一序列 |

T30/T60/T90 还要求窗口前后都有 tick（允许 10 秒行情间隔容差）、窗口内至少两次买一严格上移，并且当前买一位于窗口最高位。断流后的少量新 tick 不会被当作完整窗口。这个连续性门仅用于新增快速分支，原有 150/300 秒盘口模型的阈值和窗口语义保持不变。分钟分支在当前分钟尚未收盘时即可用截至当前 tick 的临时 OHLC 触发，因此比历史一分钟 K 回测更早，也可能产生更多误报。

## 锁存和审计

- `premium`、`pull`、`radar` 各自独立锁存。
- radar 首次满足立即提醒；强度比上次提醒再升至少 0.20 个百分点，或已过 60 秒且创新高，才重复提醒。
- 所有 radar 条件连续 30 秒不满足后重置。
- `model` 示例：`radar`、`premium+radar`、`pull+radar`、`premium+pull+radar`。
- `reason` 记录当帧实际命中的原因代码。
- 8421 signal 和 summary 新增快速买一、分钟动量、自适应动量、分钟振幅及历史基准字段；全部是 ppm 定点整数。
