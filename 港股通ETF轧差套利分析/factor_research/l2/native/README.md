# C++20 L2 内核与盘中批量入口

已实现 CSV 解析、按真实订单引用归并、沪深分别恢复委托生命周期、主动/被动成交、分钟与短时间成交簇聚合，提供 CLI 和 pybind11 接口。它重建已观测成交及订单数量，不模拟交易所重新撮合，也不声称恢复缺失的原始委托或完整价格队列。

## 构建和测试

需要 CMake ≥3.19、C++20 编译器；Python 扩展另需 Python、pybind11、NumPy。批量研究另需 pandas。

```sh
cmake -S native -B native/build -DCMAKE_BUILD_TYPE=Release \
  -DETF_L2_BUILD_PYTHON=ON -DPython_EXECUTABLE=/absolute/path/to/python
cmake --build native/build -j4
ctest --test-dir native/build --output-on-failure
```

纯 C++ 可省略 Python 选项；`-DETF_L2_SANITIZE=ON` 启用 AddressSanitizer/UBSan。macOS 已实测；尚未在 Windows 编译运行验证，不能把源代码的 MSVC 支持视为 DLL 已验收。

```python
import etf_l2
r = etf_l2.process_files(
    trade_file="逐笔成交.csv", order_file="逐笔委托.csv", quote_file="行情.csv",
    code=513330, date=20260427, unit=1000000, cutoff="14:45")
```

`unit` 必须来自该日 PCF；例值仅演示接口。`orders/minutes/bursts` 为只读 NumPy 列，零复制视图由 capsule 持有原生结果；Python 调用释放 GIL。`audit` 给出数量守恒、未知原量、数据质量和成交总额对账；`timing` 给出解析及各阶段耗时。内存预算是保守估计的准入检查，不是操作系统 RSS 硬限制。

CLI：

```sh
native/build/etf_l2_cli 20260427 513330 1000000 trades.csv orders.csv quotes.csv output_dir 14:45
```

成功输出订单、分钟、成交簇 CSV 和最后写入的 `summary.json`。已有完整输出拒绝覆盖。退出码：0 正常；2 数据质量未通过；1 异常；64 参数错误。源码数据始终只读。

## 沪深与时间约定

- 六位代码确认市场；5 开头的目标 ETF 按上海处理，即使源文件错误标为 `.SZ`。
- 上海 A 记录代表挂单剩余量；原量仅在证据充足时等于该余量加初始主动成交。不存在 A 的立即成交单标为原量未知，只保留已观察下界。集合竞价量不会误加为初始主动成交。
- 深圳委托保留 0/1/2/U 子类型，撤单从成交流 C 记录提取；不为零价格 U 单杜撰价格。
- 支持 GB18030、UTF-8/BOM、可选尾空列，以及上海空成交代码的单个 NUL 导出形式；未知实质代码仍拒绝。
- 同毫秒跨流没有可靠公共顺序时标记歧义。订单引用、时间冲突、超额成交等不能通过的数据质量门槛会阻断因子。
- 默认 `cn_etf_2026_h1` 支持 2026-01-01 至 2026-07-05；其他历史日期必须显式指定下文的已验证 profile。
- 截断为严格 `event_time < cutoff`；14:30、14:45 不读取截断后的委托原量、成交或行情。完整分钟以结束时间标记。

## 批量与研究模型

`batch/intraday.py` 支持文件快照、PCF 可知时间、逐分钟溢价上下文和可替换 provider。14:30 计算 210 个交易分钟，14:45 计算 225 个；排除午休和 ETF 闭市之后的分钟。禁止把当日最终结算汇率作为盘中可用输入。

QMT 传输按用户要求暂不接入。无模型时只输出因子；旧 JSON 线性模型入口与 `../study/` 的非线性研究模型格式不同。后者用 `../study/score.py` 计算，不能把 joblib 文件传给线性模型入口。

回归测试覆盖生命周期、重复与冲突、撤单、沪深竞价时段、整数溢出、编码、零复制生命周期、多线程、截断后的未来数据污染及批量输入约束。`tests/validate_real.py` 对真实 CSV 另用 pandas 独立聚合逐订单核对八个数量字段，并对账成交额、分钟量和行情累计量；回执在 `validation/`。
