# 04 桥接协议与未来 C++ 预留

## 1. 两层稳定边界

统一系统定义两条互不混用的合同：

1. **业务数据合同**：继续兼容现有 8080/6787/8421/19195/18765 协议；
2. **本机管理合同**：`machome-hub-ui ↔ machome-hub-agent` 的 0600 QLocalSocket JSON-RPC。

管理合同不能直接向 LAN 暴露，不能携带任意 shell，不能包含 TGW/QMT/Webull/PushPlus 密钥。

配套机器可校验 schema：

- [module-status.schema.json](../contracts/module-status.schema.json)
- [module-command.schema.json](../contracts/module-command.schema.json)
- [module-event.schema.json](../contracts/module-event.schema.json)

## 2. C++ 抽象接口

建议接口是源代码级 C++ API，后台通过 QObject queued signal 传不可变快照：

```cpp
class IModuleBackend : public QObject {
public:
    virtual QString moduleId() const = 0;
    virtual ModuleCapabilities capabilities() const = 0;

public slots:
    virtual void start() = 0;                         // 启动 adapter，不等于启动业务
    virtual void stop() = 0;
    virtual void requestSnapshot() = 0;
    virtual void submit(ModuleCommand command) = 0;

signals:
    void snapshotChanged(ModuleSnapshot snapshot);
    void detailEvent(ModuleEvent event);
    void logBatch(QVector<LogEvent> events);
    void commandChanged(CommandResult result);
};

class IModulePageProvider {
public:
    virtual QList<RouteDescriptor> routes() const = 0;
    virtual QWidget *createPage(QStringView route, const QVariantMap &context,
                                QWidget *parent) = 0;
};
```

约束：

- `QWebSocket`/`QNetworkAccessManager` 必须在所属 adapter thread 内构造；不能主线程构造后随意 move。
- 跨线程只传 value type/不可变快照；模型更新回 UI 线程。
- command lane 与 telemetry lane 分离；telemetry 可合并，command/result 不可丢。
- UI 页插件只做呈现，不承载业务服务和阻塞 SDK。

## 3. Wire framing

QLocalSocket 使用明确帧边界：

```text
uint32 big-endian payload_length
UTF-8 JSON payload
```

限制建议：

- 单帧默认 1 MiB；日志/历史用分页或 chunk，不发巨型 JSON；
- 首帧必须 `hello`，校验 `protocol=module.control.v1`、peer UID、客户端版本；
- 双方有 `instance_id`、递增 `sequence`、UTC wall clock + monotonic age；
- 未知可选字段忽略，未知 enum/必填字段拒绝并可解释；
- 每条 command 都有 `command_id`，结果可重查；
- socket 文件 0600，父目录 0700，并校验 peer UID 501。

## 4. Build manifest

当前多个模块不能证明部署内容与源码一致，因此每个新构建都生成：

```json
{
  "schema_version": 1,
  "module_id": "premium",
  "version": "0.4.0",
  "git_commit": "...",
  "git_dirty": false,
  "built_at": "2026-09-04T01:00:00+08:00",
  "compiler": "AppleClang ...",
  "qt_version": "6.10.2",
  "arch": "arm64",
  "protocols": ["premium.monitor.v2", "premium.l1.v1"],
  "artifacts": [{"path": "bin/etf-premium-core", "sha256": "..."}],
  "source_inputs": [{"path": "src/server/CoreServer.cpp", "sha256": "..."}]
}
```

运行时 status 额外返回：`build_id`、`config_hash`（先规范化并排除密钥值）、PID、started_at、boot_id。首页只显示短 ID，详情可查看完整 manifest。`git_dirty=true` 必须显式显示，不能用版本号伪装可重现构建。

## 5. 四个 adapter

### 5.1 UploadModuleAdapter

读取：

- 精确 launchd label/ProgramArguments/PID；
- `scripts/.runtime/upload_health/*.json` 原子状态；
- 8080 `/api/v1/health`、uploads status/debug status；
- 业务时间戳、ACK、stale 和最近失败；
- 增量日志。

控制：首期只读。后续由 agent 对白名单 label 执行 launchctl 动作；网站和 uploader 分开，命令参数是固定 module/subservice ID，不接受路径或 shell 字符串。

未来 C++：

- 用 QWebSocket/QNetworkAccessManager 实现新 uploader；冻结 JSON v1 和 CSV/分钟/anchor 合同；
- IB/TWS、持仓和历史补数可继续 Python helper，通过 QLocalSocket/NDJSON；
- Go/Vue 网站无需为了“四合一”改写 C++。

### 5.2 PremiumModuleAdapter

读取：

- loopback 8421 `status/sync/summary/signal/detail`；
- 19195 仅 `status/ping`；
- console/core/TGW 精确 PID、父子关系、构建指纹；
- 持久化/PushPlus/磁盘/队列指标。

控制：观察清单和 L1 热清单可复用现有 loopback JSON 操作；生命周期放在新管理面。Hub 绝不连接私有 `tgw.sock`。core 故障按 core+TGW 依赖组恢复。

未来 UI 内嵌：当前 `ConsoleWindow`/`MonitorWindow` 是 final QMainWindow 且私有耦合，先抽成 `PremiumModulePage(QWidget)`、`PremiumSignalDetailWindow`、`PremiumServiceFacade`。建议与 Hub 同编译器/同 Qt 版本**源码级静态链接**；不要把不稳定 Qt/C++ ABI 当跨版本插件合同。

### 5.3 WebullModuleAdapter

读取：

- `/v2/health/live`；
- Bearer `/v2/status`、`/v2/clients`、`/v2/symbols`、`/v2/book/XOP`；
- WS `/v2/stream`；
- 复用已有 Qt client 的 Decimal、session、sequence、gap、inside market 校验。

注意：`/book` 在 stale 缓存下仍可能 200，必须以 `/status` 和本地 captured_at freshness 门控。

待在迁移副本新增的本机命令：

- `set_mode(auto|force_running|force_stopped)`；
- `start_collector` / `stop_collector`；
- `restart_browser`；
- `show_login_window`；
- `get_command_status`。

未来 C++ 顺序：

1. C++ UI/adapter；
2. 状态、日志、控制合同；
3. normalizer/store/API/PushPlus；
4. MQTT/protobuf parser 按 golden frame 逐字节对照；
5. 最后才考虑替换 Playwright/browser 捕获。

浏览器登录/profile/滑块/内部协议是最高风险，长期保留 Python sidecar 是可接受的正式架构。

### 5.4 RedemptionModuleAdapter

读取：

- 127.0.0.1:6787 `/health`，必须验证 `protocol==1` 和 module identity；
- snapshot/watchlist/history/PCF；
- `/ws/v1/changes` 的 snapshot/change/status/heartbeat；
- Wind、订阅、PCF、6787 客户端和 QMT 状态。

现有 loopback mutation 可先由 agent 封装成白名单 command。任何 Wind start/stop/cleanup 命令都按现有安全状态机执行，不允许 SIGKILL。

未来 C++ 顺序：

1. Qt6 客户端与现有全部页面；
2. Python server 继续 sidecar；
3. 将 Wind/LLDB/C probe 封成独立 `WindProbeBridge` helper；
4. 可选以 QHttpServer/QWebSocketServer/QXmlStreamReader/QSaveFile 或 SQLite 替换 Python service；
5. C probe 继续用 golden JSON 与 Python/C++ shadow diff。

C++ 重写 server 不会自动修复私有 Wind ABI 风险，必须把该依赖隔离并版本探测。

## 6. 页面兼容层

每个 adapter 返回 capabilities 和 routes。页面从能力生成按钮，而非按模块名猜测。示例：

```json
{
  "commands": ["open_legacy_ui", "refresh"],
  "routes": [
    {"id": "webull.book", "presentation": ["stack", "window"]},
    {"id": "webull.login", "presentation": ["window", "external"]}
  ]
}
```

首期兼容策略：

- Qt/PyQt 旧 app：只在 shadow/logic 兼容阶段启动或聚焦为独立窗口；不尝试 macOS 跨进程 QWidget 嵌入。owner 模式禁止 `open_legacy_ui`，因为旧 UI 会自动恢复旧 supervisor。
- Vue：外部浏览器优先，可选 QWebEngine。
- 新 C++ 页面：通过 route provider 内嵌。
- 二级页上下文使用稳定业务 ID，不传 QWidget 指针或 Python 对象。

## 7. 安全

- Webull 行情 token 与 Hub control 凭据分离；不复制 token 到 `modules.json`。
- 账号、cookie、token、PushPlus、TGW、QMT 凭据只来自 Keychain 或权限 0600 的现有环境文件。
- config hash 对敏感值先替换为 `<redacted>`，但保留“是否已设”和结构变化。
- 日志与 RPC error 统一脱敏；剪贴板复制密钥必须有明确动作、提示和自动清除策略。
- 管理 RPC 仅本机 UDS；如果未来远程管理，另建 mTLS 服务，不把 UDS 简单 TCP 转发。
- 所有 mutation 有审计；行情读取与管理权限分离。
