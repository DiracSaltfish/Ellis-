# 五合一界面逐页分析与调整方案

审阅日期：2026-09-08。源码基线：`97e5b63312b848ab56849c6df24fb4da023f587d`。

**结论：有明显优化空间，且有少量显示逻辑错误，应先修正，再统一布局和交互。** 已有卡片、表格和历史查询可以保留；重点重做同步模块、PCF 详情及观察列表管理，调整总览和各页的空间分配。

本轮仅分析、离线预览和编写方案，没有改业务源码、部署、连接 machome 或调用交易接口。范围为原生控制台的运行总览、五模块 29 个标签页，以及行情详情、PCF/QMT 详情和提醒设置。包内 Upload 网站通过外部浏览器打开，不计入本次原生页面视觉审阅。

离线预览使用生产页面组件，四模块使用已保存的历史快照，同步模块使用已有预览样本；生成 1440×940、1120×760 两档共 70 张图片。逐页检查小窗口布局，并核对重点大窗口页面。历史查询、信号事件、盘口详情没有在预览中实时请求，相关空表不能据此认定为线上缺数据。详情弹窗本轮按代码审阅，尚未做完整视觉回归。预览工具未构造 HubClient 或 Agent。

**二、逐页调整：运行总览**

建议保留侧边导航和现有蓝灰配色，把总览改成“状态汇总 → 模块卡片 → 最近事件”。

- 顶部显示后台连接、最后心跳及异常/休眠模块数量。后台心跳与行情更新时间分别显示。
- 五张卡各自使用本模块指标。同步模块不参与交易时段休眠统计；其常驻状态应单独表述。
- 卡片保留“查看服务”，点击指标或异常可跳到相应标签并自动筛选。刷新可以合并到全局工具栏，减少每卡重复按钮。
- 最近事件支持模块/结果筛选、复制、查看完整内容。时间列避免截成“09-07 …”。无事件时显示说明。
- 全局工作/测试模式放入可展开的控制区，显示作用范围及每模块执行结果。

| PCF：成分证券 | 将整个数组 pretty-print 为 JSON。成分多时难以比较和定位。 | 成分表：代码、名称、数量、替代标志及已有现金字段；支持搜索、筛选、数值排序、复制/导出。不同数据来源字段先映射核实。 |
| PCF：QMT1 / QMT2 | 每页还含连接/资金树、持仓表、委托表、指令结果文本，以及申购/赎回按钮。 | 根据“服务端只监控”的使用方式，将 QMT 收入默认折叠的高级诊断，默认不展示交易按钮；不自动连接。保留必要的只读诊断入口，并清楚显示启用条件。 |
| QMT：连接/资金 | 原始字段树。 | 连接摘要和只读资金卡，原始字段折叠；数据未同步时不能填 0。 |
| QMT：持仓 / 当日委托 | 普通表格，缺筛选与长委托号详情。 | 搜索/筛选/复制完整标识；不因 UI 改版触发查询以外的业务操作。 |
| QMT：最后指令结果 | 原始 JSON。 | 提取指令、时间、状态、原因和关联 ID，原文折叠。 |
| 提醒设置 | 已有提示音、音量、重复、时长、冷却表单；外部音频字段始终展示。 | 按选择显示相关字段，汉化保存/取消；可增加明确的本地试听，不混淆为真实业务告警。 |

PCF 代码位于 `ModulePages.cpp:2144` 和 `:2359`；行情详情在 `:940`。PCF 字段卡改版需逐项核对实际返回结构；不能假设所有来源都有同名字段。

**九、统一高度和交互规则（建议值，实施后按实测调整）**

| 区域 | 建议 |
|---|---|
| 主窗口 | 先保证 1120×720、1120×760、1440×940 都可用；不能仅靠把最小窗口放大来规避问题。布局尺寸采用 Qt 逻辑像素。 |
| 页头 | 标题、简短描述、状态和主要操作保持紧凑；过长操作组在窄窗口换行或进菜单。 |
| 总览卡片 | 内容最小高度约 170–190；空间不足滚动。按可用内容宽度排 1–3 列，不强行固定三行后再压缩。 |
| 指标卡 | 建议高度约 90–112，最多一行提示；长异常原因移到独立信息区。四卡在窄内容区可改两列。 |
| 概况摘要表 | 高度按表头加实际行数计算；通常展示 5–6 行，更多使用“查看全部”。不再对所有概况表统一设至少 260。 |
| 主业务表 | 占满剩余空间；不加外层同方向滚动。默认行高 32–36，提供紧凑模式；空表显示具体原因，少行无需为了占满而把行拉高。 |
| 列宽 | 代码约 90，名称约 160–220，时间约 150，状态约 100；数值右对齐。实际宽度依字体调整；保存列宽、顺序、显示列。 |
| 详情 | 宽窗口用可拖动侧栏，小窗口用独立详情窗；不让详情持续挤占主要列表的高度。 |
| 表单 | 常规设置限宽约 600–760；长列表不设 150 高的硬上限；说明文字按需折叠。 |
| 事件区 | 默认显示数行，支持展开和拖动；隐藏不丢事件。 |
| 控制反馈 | 发起后显示“执行中”，收到回执再更新成功/失败；同一维护操作进行中避免重复点击。只读状态可查看和复制，写入按钮禁用并说明原因。 |

普通业务表统一提供搜索、合适的筛选、选中行详情、复制以及空态。并非每页都要增加修改按钮：日志、诊断、历史和客户端状态最需要的是查找、定位、比较及导出。

中文显示还需清点：上传任务里的 `fault`、`private_ipc`、技术来源名，原始 UTC 时间，以及托盘仍写“四合一”。保留 IBKR、QMT、ETF 等常用名称；IOPV、PCF、TEMP 增加中文说明。数值缺失显示“— / 未报告”，只有确有数据的 0 才显示 0。

**十、实施顺序与验收标准**

1. **第一批：显示正确、窗口可用。** 修正同步卡片、全局模式统计、总览裁切；调整拥挤工具栏、概况滚动、列表高度；统一缺数据/休眠/错误文案。
2. **第二批：重点页面结构化。** 同步四页、PCF 两个主要页、观察列表和业务详情；补权限/忙碌反馈、阅读位置保存。现有协议内优先完成。
3. **第三批：通用交互和一致性。** 统一搜索、排序、列管理、日志查看器、中文和时间显示；建立稳定行 ID 后再启用实时表排序。
4. **单列后续能力：** Upload 原生完整明细、同步完整历史/版本比较、Webull 运行时切换标的。它们需要额外接口或引擎支持，不应包装成纯样式改动。

建议验收清单：

- [ ] 三档窗口逐页检查，标题、操作、筛选框完整可见；主表有足够高度，必要内容能滚动到达。
- [ ] 五模块总览各用自身指标；四采集模块切换模式后不因同步模块而永远等待。
- [ ] 正常、休眠、无数据、未接入、断线、长错误等状态有区别；不把历史快照当作实时数据。
- [ ] 同步设备缺 ack、待上传、无提交、多设备、多提交时都能准确显示；最近提交不冒充完整历史。
