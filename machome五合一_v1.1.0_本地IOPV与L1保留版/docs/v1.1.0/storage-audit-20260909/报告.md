# IOPV 分钟存储实测与优化建议

正式机 192.168.1.113；2026-09-09 SQLite 在线 backup 得到一致副本，在本地副本上实验。未修改正式数据库、程序或保存精度。以下 MB/GB 使用十进制。

## 当前占用

主库 155,271,168 字节（155.3 MB），WAL 3,489,672 字节，SHM 32,768 字节。WAL 是临时写前日志，不能把每次写入的 WAL 字节累计当作永久增长。

分钟 43,124 行：当日 41,132 行/121 个标的；另外 6 个历史日各 332 行。实时 22,680 行，历史重算 20,444 行。实时 JSON 平均 3,301 字节，重算平均 1,364 字节，不能用混合平均低估全天实时保存量。

按 dbstat，分钟表 133.50 MB、分钟索引 1.66 MB；汇率表 18.04 MB；PCF 表 2.96 MB。minute payload 保存完整 Point JSON，包含名称、日期、PCF 哈希、各时间戳、五档、五档三个溢价率及状态。逐字段 JSON 大小统计中 book_premiums 约 42.17 MB、book 约 10.14 MB，是主要重复负担。

## 同一份 43,124 行副本对比

| 方案 | 分钟库含索引 | 内容变化 |
|---|---:|---|
| 原始记录重新建库 | 134.97 MB | 无 |
| JSON 去空白 | 122.79 MB | 数值不变；主要改变回填数据的空白 |
| 去空白并 ETF 3 位、IOPV 4 位 | 122.65 MB | IOPV 精度降低；相比仅去空白只省 0.14 MB |
| 每行 zlib 无损压缩 | 45.27 MB | 逐行解压字节一致，保留全部精度与盘口 |
| 定点图表表 + 压缩质量标记 | 19.11 MB | 保留价格、三种 IOPV、时间/来源/质量标记；不保存历史五档和原始派生溢价率等完整 Point 字段 |

所有方案均验证行数一致；无损方案逐行校验原始 JSON 字节。定点方案使用 decimal ROUND_HALF_UP，NULL 保持缺失，不用 0 冒充缺失。

ETF 样本全部已经是 3 位以内，转换最大误差为 0。IOPV 四位转换实测最大误差约 0.00005 元/份；重新算溢价率最大差约 0.014708 个百分点（约 1.47 bp）。因此只在归档/展示阶段量化，实时核心、API 信号判断保留原始精度。若关注接近零的穿越，可考虑 IOPV 六位或保留原精度无损压缩。

SQLite REAL 通常使用 8 字节，INTEGER 按量值使用可变长度；把 REAL 四舍五入并不意味着固定减少存储空间。定点要实际存 INTEGER，例如 ETF 0.980 -> 980，IOPV 0.98519677 -> 9852（读取为 0.9852）。

## 每天和长期增量

代码 ChartMinute 包括 09:30–12:00 与 13:00–16:08，共 340 个分钟槽。按 121 个标的全覆盖：41,140 行/交易日。以实时样本重建、VACUUM 后含索引的实际每行占用外推：

| 方案 | 分钟本身/日 | 加 PCF/汇率后预算/日 | 250 交易日预算 |
|---|---:|---:|---:|
| 当前结构 | 170.34 MB | 185–195 MB | 46–49 GB |
| 仅缩短 JSON 小数位 | 170.34 MB | 185–195 MB | 46–49 GB |
| 完整快照无损压缩 | 50.75 MB | 55–60 MB | 14–15 GB |
| 精简定点图表归档 | 17.91 MB | 22–26 MB | 5.5–6.5 GB |

后两行假设 PCF/汇率原文也压缩。当前 127 份 PCF 原文字节 2.875 MB -> 0.240 MB；2,199 份汇率 14.533 MB -> 3.911 MB。新时段 08:40–16:10 按每 15 秒约 1,800 份汇率/日；索引和 SQLite 页分配另计。

这些是容量规划外推，不是已观测完整多日稳定增长。随 JSON 状态长度、成功覆盖数和索引页利用率变化。未计其他五合一模块、行情日志、历史回填、备份副本；WAL、临时迁移库需要另留峰值余量。若保留两份完整备份，占用应相应增加。

## 建议实施结构

1. 先做版本化无损压缩，读路径支持旧 JSON 和新压缩 BLOB；保留当前查询主键，迁移前备份，回放 API 输出验证一致。风险最低，已测约节省 2/3 分钟库。
2. 图表长期表使用 INTEGER 定点：fund_id、trade_day、minute_of_day、etf_milli、mid/buy/sell_iopv、quality_ref，复合主键 WITHOUT ROWID。按标的日期读取，不单独重复同一个主键索引。示范实现保留字符串 symbol 以避免把未测的进一步优化算入节省量。
3. 日级元数据存名称、份额、现金、PCF 引用；汇率快照全局共享，以 fx_id 引用。状态/来源使用字典引用。五档溢价率可按盘口价格和相应估值派生，不逐档重复保存三个结果；但应保留历史有效性规则及原精度，否则重建数值可能改变。
4. 可选择“近 30 个交易日完整压缩快照 + 更早精简图表归档”。这会改变历史审计能力，需要明确保留策略后实施。当前研究未自动删除五档或历史数据。
5. PCF 原文按内容哈希去重并压缩；汇率保留有效来源时间与状态，不因报价重复就删除失效状态。按日分块压缩可能更省，但需要解块成本和随机读取测试，尚未纳入实测结果。
6. 迁移在新库完成，校验总行数、每标的每天行数、NULL/状态、解压一致性、历史图/API兼容以及最新 calculated_at 覆盖规则，再原子切换。运行库不直接就地大规模 VACUUM；清理/归档不自动等于文件立即缩小。
