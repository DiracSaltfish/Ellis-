# 港股通实时申购赎回：实现评估

日期：2026-09-15。范围：本地源码、用户提供的 webarchive、ssh machome 只读核查。未修改线上配置、订阅、程序或进程；未进行新标的实盘订阅验证。

## 结论

建议在现有 RedemptionEngine 中增加独立功能池，复用一个 Wind helper 和原有 TBAPI2 订阅方法，拆分采集集合、池内状态、展示、历史及提醒策略。首期提供五合一原生页面和现有内网页面，比例提醒与外部客户端接口默认关闭。无需另开一个 Wind 实例或第六个业务进程。

## 标的范围

严格只解析归档 HTML 的 flex_qdiia 亚洲市场表，而不是整个页面：它还保存了隐藏的欧美和商品表。

亚洲表有 104 个以 1 开头的条目；其中 6 个 LOF，1 个日经 ETF（159866，已在旧池）。排除这 7 个后得到 97 个香港方向 ETF 候选，与旧七只不重叠。必须保留 158000、158003，不能写死为 159 前缀。

这 97 只是候选，不应把“香港方向 ETF”直接等同为已核实“通过港股通投资的 ETF”。名称含港股通不是完整分类条件；恒生科技、恒生指数等产品需要用已有产品元数据、基金资料或 PCF 核对投资通道。正式种子池保存代码、名称、来源、分类与纳入理由，待核实项明确标记。归档是本次清单来源，不代表自动同步今后集思录新增产品。

## 建议的数据与采集结构

1. 保留 legacy 旧池，新增 hk_connect 池；允许标的同时属于多个池，底层按 Wind 代码去重订阅。
2. 旧 watchlist 配置与旧接口语义保留；新增池用独立配置键及开关。历史增加 pool_id（或独立表），迁移前历史全部归 legacy。无池参数的旧历史接口仍只返回旧池。
3. Wind 采集标准化只做一次，再按池路由。内部完整快照与旧兼容快照分开构建；旧接口快照、实时事件、历史、PCF 列表和单标的查询都必须过滤旧池，不能只在 UI 隐藏。
4. 新池变动使用独立事件类型；不能沿用 redemption.change 去触发现有 UI 提醒。提醒配置、冷却、去重及以后外发策略按池隔离。
5. 新池采集状态逐标的展示：待订阅、订阅成功待首帧、已有数据、失败、过期；“无数据”不能显示成 0。

### 必须处理的扩容风险

app/helpers/wind_probe/main.cpp 的 subscribeLive 当前会先撤销已有 sessions，再逐标的复制探针、生成 LLDB 命令并一次执行；单个标的约 10 条命令，runLldb 最长 45 秒。任何一只验证失败会撤销整批 planned 订阅。

因此即使界面允许 200 个标的，也不能据此认定百只订阅可靠。应在同一 helper 内增加增量、分批订阅及逐标的失败隔离，先保留旧池会话，再添加新池；删标的只有在所有池均不需要时才停订。重连可以重建全部需要的会话，普通新池编辑不能重订旧七只。不能简单分批调用现有 subscribeLive，否则下一批会撤销上一批。

分批大小与时间预算通过交易时段试验决定。先验证少量新标的首帧、有效字段和后续回调，再扩大到全量。发生失败时保留明确状态与有限重试，避免盲目反复附加 Wind。

现有原始采集以每标的最新 JSON 文件落盘、helper 每秒扫描。页面可按 1 秒左右合并更新；不得每次变化都把百只标的完整 PCF 广播到所有页面。最新快照适合累计量查询；未来若要求每个回调完整历史或精确短窗口统计，需要评估追加式事件保存，不能假设当前每秒扫描已经保存全部推送。

## 篮子与比例口径

复用现有 etfbuynumber、etfbuyamount、etfsellnumber、etfsellamount 字段。现有 Core 将 amount 按申购/赎回份额处理；篮子应按当日有效 PCF 的最小申赎单位换算，不能把 number 直接当篮子。

设申购份额 B、赎回份额 S、每篮份额 U：申购篮子 B/U，赎回篮子 S/U，净篮子 (B-S)/U。两边均有效且 S>0 时，申购赎回比 B/S；同一标的两边单位相同，比例可直接用份额算。缺少有效 U 时可展示原始份额及份额比，但篮子数必须显示待确认，不能冒用其他基金的篮子单位。

申购 5 篮、赎回 1 篮：比值 5:1，净申购 4 篮。它不等于旧逻辑中的“反向份额变化释放申赎容量”。新池需要独立计算器，不能直接套用 classifyIntradayOpportunity 的机会方向。

首期预留 enabled=false、统计口径（当日累计/时间窗口增量）、申购方向阈值、赎回方向阈值、最少篮子、净篮子门槛、冷却与重新触发条件；阈值暂不设有效默认值，5:1 仅是示例，不作为已确定规则。

0:0 显示无申赎；B>0/S=0 显示仅申购；B=0/S>0 显示仅赎回，不将除零伪装成一个普通数值。累计量回落、跨日、回放、过期/缺字段数据需要专门基线与质量处理。缺少历史的窗口指标显示等待积累。后续提醒建议同时有数量下限和比例条件，首次越线后去重，避免比值持续满足时每帧重复提醒。

## 原生 UI 与网页

- 五合一申赎模块增加“原有申赎监控 / 港股通实时申购赎回”两个页签；旧按钮只作用旧池，新池有独立清单和状态。
- 新池表格：代码、名称、申购份额、赎回份额、申购篮子、赎回篮子、净篮子、申赎比、更新时间、订阅/数据状态；支持搜索、排序与变化详情。
- 80 端口现有站点导航新增“港股通申赎”，建议路径 /hk-connect-redemption。复用既有 Go 服务承载页面。
- 网页数据推荐由 Agent 发布精简的新池只读快照到独立本机通道：首期可采用带序号和时间的原子快照文件，Go 服务读取并缓存；后续历史需求可增加本机只读 IPC。不要让浏览器直接读数据库，也不要复用旧 6787 全量输出。
- Go 服务提供仅为页面使用的只读数据路由，沿当前 80 端口访问。这里“无外部接口”解释为不向既有第三方客户端发布兼容 REST/WS 协议；网页正常工作仍然需要页面数据通道，不应把页面数据路由称为完全没有接口。
- 浏览器关闭不影响订阅。网页明确标注交易日、服务时间、数据时间、断线/过期状态和“提醒未启用”。初期网页不增加订阅编辑或交易动作。

## 实施与验收顺序

1. 确定候选池分类，冻结有来源的种子清单；完成向后兼容的数据迁移与回放测试。
2. 完成 helper 分批/增量能力，测试某只失败不会停掉旧七只；重复增删不会产生重复订阅，退出能准确停订。
3. 完成原生与网页展示，验证同一代码同一序号数据一致，断线和无数据正确显示。
4. 验证新池变化不会进入旧 REST、WebSocket、历史、PCF 单标的接口及弹窗/声音；旧池仍按原行为工作。
5. 在交易时段分阶段验证有效首帧、持续推送、PCF 篮子单位、资源使用和重连；97 只是清单规模，Wind 权限/字段覆盖/容量尚未实测。
6. 更新需构建的 Agent/UI/helper 和网页服务，保留完整生产备份及可回退的数据迁移。打包后核验签名与 ABI manifest；当前版本有近期 Wind 授权/探针校验修复，不能整包覆盖回旧清单。

这是一次中等范围的功能扩展，主要工作在订阅失败隔离和旧接口/提醒兼容；单纯加一个列表或页签不足以满足要求。
