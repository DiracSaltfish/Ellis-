# 常驻运行与自动换日验收

检查前：启动立即拉取 PCF，其后每 5 分钟全量拉取，没有固定日内时间。报价、PCF 和汇率已有日期门禁，但没有统一清空跨日状态；订阅集合不变时不会主动重订阅；网页停留在昨日日期。

修复后（北京时间）：
- 零点由每秒主循环识别日期改变，清空实时篮子、报价、汇率、快照和订阅计划。未写入的上一日分钟仍按原日期落盘，SQLite 历史保留；停牌核实按日期查询，不继承。
- 周一至周五 08:40 首次自动拉取。拉齐 120 只后当天不再定时重复拉取；不齐每 5 分钟重试至 16:08。晚启动/恢复在 08:40 后立即补拉一次；收盘后补拉失败不无限重试。人工刷新不受定时限制。
- 未接入独立节假日日历：非周末休市日仍尝试当日 PCF，由日期校验拒绝旧 PCF，不借昨日数据估值。
- 全部当日 PCF 就绪后重建去重订阅；跨日先清空计划，因此即使新旧成分完全一致也会重新订阅。原 L1 转发服务无需重启。
- PCF 网络调用跨越午夜时禁止把旧日结果发布进新日状态。数据接口继续按 trade_date 隔离；网页查看今日时自动跟随换日，主动查看历史时保持所选日期。
- 运行管理显示数据日、PCF 定时时间、上次与下次拉取时间。

守护核对：正式 Agent 和 80 端口入口均 RunAtLoad=true / KeepAlive=true；IOPV helper 退出由 Agent 在 10 秒后拉起；共享 L1 读超时 35 秒，心跳 10 秒，失败重建连接与订阅；主机 AC sleep=0。进程重启、L1 保留已有实际验收。

边界：这些是用户登录会话中的 LaunchAgent，不是开机前的系统守护。主机 autorestart=0；断电后的自动开机、未登录时启动不在已通过的保证范围，本次没有改动系统登录/电源策略。不能将仿真跨日测试宣称为已完成真实隔夜或全天稳定性观察。

验证：Go 全量 race 测试和 vet 通过；涵盖 08:39/08:40、5 分钟重试、晚启动、周末、UTC 与北京时间、跨日清状态且旧分钟保留、相同成分的真实 TCP 重新订阅。浏览器日期跟随与历史选择保留测试通过。证据 rollover-tests.log。
