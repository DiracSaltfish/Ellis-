# 05 迁移、部署、切换与回滚

## 当前实现状态

M1-M4 所需的 UI、Agent、四个 adapter、逻辑控制桥、审计和交付/回滚脚本已经在本机实现并通过自动化；生产示例仍锁定 shadow。M5 的真正 owner 交接没有执行，也不能由本地 mock 代替。真机按 [09 手册](09_machome真机验证与切换手册.md) 逐模块验收，owner 候选配置、一次性 marker、旧 supervisor 清单与回退顺序详见 [10 owner 接管演练](10_owner接管与回退演练.md)。任何时候都不得一次接管四项业务。

## 1. 原则

- 一次只迁一个模块；其他三个保持原 owner。
- 先观测、再页面、再控制、最后才考虑换后端语言。
- 任何时刻只有一个写者/订阅 owner，shadow 客户端只能读。
- 生产配置和运行数据原地保留；新应用首次启动不自动搬迁。
- 每个阶段均有独立 feature flag 和回滚开关。
- 版本无法证明、验收缺项或回滚未演练时不得切换。

## 2. Phase 0：冻结合同与建立基线

产物：

- 远端实际 ProgramArguments、label、PID、父子关系、端口、配置结构；
- 每个二进制、关键 Python/Go/Vue 文件、plist、probe 和 web 资源的 SHA-256；
- `build_manifest.json` 与脱敏 `config_hash`；
- 各协议 golden input/output；
- 正常交易日的 p50/p95/p99、队列、CPU、内存、磁盘、数据 age；
- 四套旧 UI 的逐页截图/录屏与功能清单；
- 原 LaunchAgent 和 app 包备份位置、回滚命令手册。

门槛：本机与 machome 版本差异已解释。本轮已确认 newnavnav、premium 存在差异，因此此门槛尚未完成。

## 3. Phase 1：只读 Hub

部署：

1. `machome-hub-agent` 以新的 LaunchAgent 常驻，只做读取；
2. `machome-hub-ui` 连接 agent；
3. 四个 adapter 均 `control_enabled=false`；
4. 首页、详情、日志、构建信息可用；
5. 四合一内建二级页可用；已确认会自启旧 supervisor 的旧 UI 不得由 Hub 打开。

不得：load/unload/kickstart 任何旧 label；连接 premium 私有 UDS；发送实时申赎 mutation；启动第二个浏览器 collector 或 Wind 订阅。

验证：至少覆盖一次完整 A 股 + 美股交易时段和一次自然跨日。新旧页面同时观察，但不得造成重复业务写入。

## 4. Phase 2：页面平移

顺序建议：

1. Webull C++ 页面：已有 Qt client，协议边界最清晰；
2. 实时申赎 C++ 客户端页面：冻结 HTTP/WS v1，Python/Wind 不动；
3. premium A-console 页面抽库：core/TGW 不动；
4. upload：保留 Web 深链，新增进程组运维页面，不重写网站。

每个页面保持“打开旧页面”回退，直到本模块专项验收全部通过。旧页面与新页面只能读取同一个服务；控制仍由旧 owner 执行。

## 5. Phase 3：逻辑控制 pilot

先开放不会终止服务的动作：

- Webull `auto/force_running/force_stopped`、restart browser、show login；
- 实时申赎已有 loopback monitor/Wind/PCF mutation 的受控封装；
- premium 清单管理的既有 loopback 操作；
- upload 的 refresh/health probe。

要求：

- 命令白名单、幂等 ID、expected revision、deadline、最终状态验证；
- UI 关闭不影响动作；
- 同模块串行、跨模块并行；
- 审计完整且脱敏；
- 旧 UI 同一动作入口在 pilot 时明确只读或协调锁，避免竞态。

## 6. Phase 4：生命周期 owner 交接

仅在预约维护窗口逐模块执行。`config/modules.owner.template.json` 故意不可运行，只能按 [10 owner 接管演练](10_owner接管与回退演练.md) 复制为单模块、单窗口候选，并对最终 plist 生成精确身份证据。通用流程：

1. 记录 pre-cutover 快照、构建与配置 hash；
2. 将模块置为安全 idle，等待进行中批次完成；
3. 释放旧 owner lease；
4. 禁用旧 owner 的自动拉起职责，但保留文件；
5. hub-agent 获取 lease；
6. 按依赖顺序启动并通过 readiness；
7. golden/smoke；
8. 观察窗口；
9. 若失败，释放 hub lease，恢复原 owner 与原配置。

### 6.1 Upload

- website 与每个 uploader 单独交接，不整组停。
- 精确 LaunchAgent label；不能按 Python 进程名。
- 交接时检查单实例 flock、health JSON PID 与最近 ACK。
- 保持原 WS session/反向请求/quote store 语义。

### 6.2 Premium

- A-console 当前是 core/TGW owner。
- 交接时 core + TGW 作为一个依赖组；避免两个监管器同时启动。
- 启动必须确认 8421、19195、TGW login/subscribe、watch/hot ready。
- 失败时恢复旧 A-console 托管；原 config/data/log 不覆盖。

### 6.3 Webull

- 首选继续让 launchd 管 Python sidecar，Hub 只做内部 collector 逻辑控制。
- 若以后让 hub-agent 管服务，必须先取消旧 KeepAlive，否则“停止服务”会被立即拉起。
- 只要开放任何 Webull mutation，必须同时配置数据 API `token_file=runtime/api.token` 和独立控制 `control_token_file=runtime/control.token`；两者都是不同的绝对路径、当前用户所有且文件精确 `0600`。
- Chrome profile、token、data 保持权限与原路径，迁移前复制快照但不同时使用同一 profile。

### 6.4 实时申赎

- 确认没有旧 `com.etfdelivery.monitor-server` 与内嵌服务双占 6787。
- 附着必须验证 `/health protocol==1` 和 module identity，不只测 TCP。
- Wind 停止严格：停订 → 温和退出 → 确认 → 清理；绝不 SIGKILL。
- 切换期间只能有一组 Wind 订阅和一个 6787 server。

## 7. Phase 5：可选后端 C++ 化

这不是 UI 上线的前置条件。按风险从低到高：

1. 状态归一化、日志、存储、API；
2. Python 纯计算/解析；
3. Webull MQTT/protobuf；
4. upload 的普通 HTTP/WS fetch/push；
5. IB/TWS、Chrome/WebTrade、Wind 私有 ABI 最后处理，且可永久保留 sidecar。

每个替换实现挂在同一 `IModuleBackend` 与 wire schema 后。Python 与 C++ 同时 shadow，比较字段、序列、业务输出和错误语义；不能因为“能编译”就直接切生产。

## 8. 部署布局

建议新应用自包含 Qt，不依赖 `/opt/homebrew` 的运行时路径：

```text
/Applications/Machome Hub.app
  Contents/MacOS/machome-hub-ui
  Contents/Helpers/machome-hub-agent
  Contents/Frameworks/Qt*.framework
  Contents/Resources/contracts/*.json
  Contents/Resources/build_manifest.json

~/Library/LaunchAgents/com.ellis.machome-hub-agent.plist
~/Library/Application Support/MachomeHub/
```

生产 premium core 当前仍动态链接 Homebrew Qt 6.10.2；这是现状，不要在 UI 迁移时顺带更换。Hub 自身应用 `macdeployqt` 后再 codesign/notarize（如需要），agent 与 UI 使用同一合同但可独立升级。

配置示例只含路径、label、端点和 secret reference；不含密钥值。安装程序验证路径存在和权限，但不自动修复旧模块。

## 9. 回滚触发条件

任一项触发本模块回滚：

- 版本/config 无法证明或与批准版本不符；
- 双 owner、双订阅、重复上传或端口身份不匹配；
- 业务字段/单位/时序/golden hash 不一致；
- 当前交易时段 readiness 超过模块 deadline；
- UI/agent 影响其他模块；
- 数据丢失、重复通知/订单风险、凭据泄露；
- 无界内存/队列增长、磁盘写阻塞实时链；
- 原 owner 无法在演练时恢复。

## 10. 回滚动作

1. 禁止新 Hub 命令；记录当前 command IDs 和快照。
2. 只回滚当前模块，不触碰其他三个。
3. 将新 owner 置安全 idle 并释放 lease。
4. 恢复原 LaunchAgent/A-console/PyQt owner；使用原配置与数据路径。
5. 校验进程身份、端口、订阅/上传唯一性和业务 readiness。
6. 保留 Hub 日志、manifest、失败证据；不删除新应用，改为只读。

回滚不是 `kill -9`。Wind、TGW、浏览器、上传器均按各自安全停止语义执行。
