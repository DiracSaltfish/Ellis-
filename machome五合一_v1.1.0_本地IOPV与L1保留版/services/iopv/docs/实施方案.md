# 实施方案（P0历史设计）

> 本文件保留最初规划。P1–P3独立服务现已实现并运行，现行行为、访问地址、通道规则及验收步骤以 [运行与验收](运行与验收.md) 为准。P4五合一回接仍未执行。

## 1. 模块边界

推荐首版一个 Go 进程管理下载、时钟、落库、HTTP；每个节拍通过 cgo 调用一次或批量调用 C++ 库。TGW 使用现有 helper/行情扇出，SDK 会话生命周期与估值库分离。以后五合一既可直接链接 core.h，也可订阅独立服务的 JSON 流；计算公式不在网页、交易端重复实现。

```text
每日PCF → 严格解析 → QC候选+当日门禁 → 不可变篮子版本
                                      ↓
现有国内/HKT行情 → 共享去重缓存 → 3秒节拍/3组C++计算
1navs汇率JSON → 日期/来源/方向门禁 ↗          ↓
                              Go快照仓库/分钟数据库
                                ↙              ↘
                        REST + SSE         内网图表与五档表
                             ↓
                     未来交易程序/五合一监控
```

不是每 3 秒只接收一组股票行情：全部所需证券持续订阅并更新缓存，**分组的是 ETF 篮子计算任务**。同一证券跨基金共用一份报价，汇率快照同组固定；结果保留每只基金各自的计算时间和最老成分时间，不能把三组包装成同时估值。

## 2. 首批范围和每日 PCF

候选 120 只（SH 89 单日通过、SZ 31 五日通过）；深市 34 只历史不稳定、17 只历史部分可得以及其余未通过/边界标的共 77 只暂缓。没有擅自把单日通过的深市产品全启用。

建议普通交易日 08:30 首抓，08:45、09:00、09:15 补抓，09:25 建立初始可用篮子；之后缺失标的低频重试。所有时间属于未来服务配置，本次未创建系统定时任务。按实际内地/香港/港股通日历控制，不用“周一到周五”代替节假日。

沪市使用 `downloadETF2Bulletin.do?fundCode=...`，以响应 TradingDay 判断日期。深市使用 `pcf_{code}_{yyyymmdd}.xml`。保留原始响应、SHA-256、URL、抓取时间。HTML/403/空响应、错误日期、错误基金身份、条数不符、非有限数值、未知 flag 均隔离；不能继续拿昨天 PCF 运行今天。

发现日内 PCF 变更时以新 hash 建版本，先校验、生成新的全量订阅差集并等候新增成分可用，再原子切换篮子；不逐行热改正在计算的旧篮子。旧分钟记录仍引用原 hash。

第一阶段只支持已经通过测试的股票/现金结构。除权、分红、停牌、新股、非港币计价、退市、合并拆分和特殊替代旗标逐基金确认后增补 policy；不得把所有 cash flag 做统一猜测。当前解析器对非对称必须替代现金主动拒绝。

## 3. 行情及 3×3 秒调度

历史样本得到 630 只 HK + 120 只国内 ETF，共 750 个订阅。已生成的三组工作量为 1,959 / 1,951 / 1,962 条成分，按大篮子优先平衡，稳定排序保证同一输入可重复分组。每天成分变化后重新规划，不能把历史 750 个列表写死。

已有五合一 `app/helpers/premium_tgw/SubscriptionPlan.cpp` 已核对：

| 证券 | canonical symbol | SDK market | public flag |
|---|---|---:|---:|
| 沪市ETF/股票 | 513090.SH | 101 | 10 |
| 深市ETF/股票 | 159217.SZ | 102 | 10 |
| 港股通快照 | 00700.HK | 102 | 12 |

港股通行情在这里走深港通 HKT 路由，不能写成 HKEX market；**行情路由不等于基金实际换汇通道**。行情源原始整数价格缩放、交易状态、源时间戳、接收时间戳和五档字段需在下一步适配时用真实 raw fixture 核对。不得复制生产密码到本项目。

0/3/6/9 秒计算第 0/1/2/0 组；使用 monotonic clock。延迟时跳过错过的节拍，不积压补算、不并发跑同一篮子。ETF 五档价变化可单独对最近有效 IOPV 算溢价，成本极低，无需等待其下一组；每条溢价均带 NAV age 和 ETF quote age。

现原型保守要求成分报价/接收不超过 30 秒、汇率不超过 3 分钟，未来应区分“行情快照活跃但最后成交很早”和“整条行情流中断”。不能只用最后成交时间判断不活跃股票。停牌估值必须有明确 approved valuation mark，显示估值依据及覆盖权重；当前不自动沿用旧价。

## 4. 汇率选择与输出语义

接口使用 `/api/v1/private/hk-connect-fx`，不爬网页卡片。只从 `central_parity.rate` 读取当日中间价，不能误用 `reference.mid_rate`（港股通参考汇率中点）或实时 bid/ask。通常 1–2 分钟拉取已足够，HTTP 请求不进入 C++ 热路径。

| 用户含义 | 上海字段 | 深圳字段 |
|---|---|---|
| 买入港股/支付人民币 | estimate.predicted_sell_settlement | shenzhen_estimate.predicted_sell_settlement |
| 卖出港股/收取人民币 | estimate.predicted_buy_settlement | shenzhen_estimate.predicted_buy_settlement |

主图默认产品交互可选择“买入港股情景”，但服务调用必须显式给 channel+direction，不能把默认 UI 选项认定为基金真实结算规则。第一版只显示一个已选结算情景加中间价，API 预留两方向。若基金实际同时走沪/深港股通，必须获得渠道敞口拆分才能做加权，不从 ETF 上市地臆测。

保存 trade_date、source as-of、model_version、calibration status、source actionable、方向、通道。网站失效后中间价仍可独立显示是生产版目标；当前原型 Evaluate 要求双汇率均有效才返回双估值，失效会整对留空，**不会偷偷退回交易所 IOPV**。下一阶段将质量状态拆到每个估值分支。

日内预测不可称“最终结算价”。16:00 后官网模型冻结/实际结算公布，分别新增字段，不能回写当天历史曲线。基金净值验证使用中间价，不拿结算情景 NAV 与官方 NAV 做 5bp 通过测试。

## 5. 图表与逐分钟记录

按用户参考图：上面三条线（中间价金色、预估结算绿色、ETF蓝色），下面两条溢价率线（与估值同色），共享时间轴与鼠标游标。标题标代码/名称、日期；副标题标 PCF 成分数、现金、申赎单位。结算图例完整显示通道、方向和“预估”。1/3/5日、前日/后日、交易日选择按后续网页版本实现。

- 横轴 09:30–16:08，北京时间。11:30–12:00 淡色标“A股午休、港股继续交易”；12:00–13:00 可压缩并清楚显示断轴。两个市场都午休的区间不伪造实时数据。
- 15:00 竖虚线，此后背景标“A股收盘，港股篮子继续估值”。ETF 实价线与溢价率线止于 15:00；不拿 15:00 的 ETF 收盘价计算盘后“实时溢价”。
- 16:08 是用户要求的采集终点，不代表所有交易日港股都在 16:08 才形成成交。源中 15:59 后直接 16:08 的情况保留缺口，不插造 16:00 点。停牌/半日市/台风日用交易日历和官方状态调整。
- 每分钟记录该分钟最后可用的各基金计算快照，保留 calculated_at。正常计算延迟最多约 9 秒，落库采样允许 12 秒窗口；超时留空、质量状态为 missing，不延用很久以前的值。
- 网页采用连续观察点且相邻分钟都存在才连线，空值断线；午休压缩是时间轴映射，不是删除真实时间戳。历史结算分钟缺失时显示“无历史预估结算汇率”，不能用今天或最终汇率回填昨天。
- Tooltip 同时列两种 NAV、ETF价、两种溢价率、源时刻、汇率、预测状态、PCF版本。两条 IOPV 基于同一篮子和证券价快照，区别仅在汇率假设。
- 五档表：买1–5、卖1–5、价格、数量、两种对应溢价。要卖出ETF参考 bid，要买入ETF参考 ask；未含冲击成本/税费。停市后表可显示最后报价，溢价列应禁用或明确“历史值”，原型返回 null。

SQLite schema 草案在 `contracts.sql`，以 symbol+date+minute+channel+direction 唯一键防重。单 writer、WAL、事务，写失败上报存储健康但不阻塞行情计算；历史重算独立 run_id，避免覆盖实录。当前只有采样函数和 schema，常驻定时写库还未实现。

## 6. API 约定（待服务层实现）

| 接口 | 用途 |
|---|---|
| GET /api/v1/iopv/snapshots | 全部候选最新快照与逐只状态 |
| GET /api/v1/iopv/{symbol}?channel=...&direction=... | 双估值、FX、覆盖度、时间、五档溢价 |
| GET /api/v1/iopv/{symbol}/minutes?date=YYYY-MM-DD&channel=...&direction=... | minute_points，空值保留 |
| GET /api/v1/iopv/stream | SSE fan-out，事件含 sequence、run_id，断线后先全量再续流 |
| GET /api/v1/iopv/health | 行情/PCF/FX/调度/落盘分别报告状态 |
| GET /api/v1/iopv/universe | 候选、暂缓及逐只 policy 原因 |

统一单位：NAV 元/份、price 元、FX 元/港元、premium_pct 百分数（1.2 表示1.2%，不是0.012）。空数据为 null，不返回0、不把前端显示四舍五入结果用于信号。版本 `intranet-iopv.v1`。响应带 mode=live/replay、sequence、run_id、calculated_at、valid_until、quote_min_at、etf_quote_at、pcf_sha256、fx_at、quality_reasons。

网站、API和交易程序消费同一个后端快照仓库，不各自重算 NAV。浏览器只做展示与坐标转换。内网绑定指定地址，默认 localhost；未来跨主机读取用只读 token，写入与管理接口不与行情读取混用。慢客户端只收最新快照，有界队列，不能反向堵塞行情线程。

## 7. 分阶段实施与验收

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| P0 本轮 | 公式、120候选、C++原型、Go适配、回归、时段/API设计 | 本地测试通过；真实沪深PCF探针；限制逐条可见 |
| P1 数据入口 | 全量每日PCF任务、真实TGW只读适配、行情时间/单位、基金通道policy | 750基线订阅可去重；当天数量按新PCF变化；每只缺失显式可见 |
| P2 常驻服务 | 3秒轮转、缓存版本切换、分支质量、分钟SQLite、REST/SSE | 一整交易日shadow；无积压；每分钟可追溯；断网/重连/换日可恢复 |
| P3 网页 | 三线NAV、两线溢价、09:30–16:08、五档表、历史日期 | 同一时刻网页与API一致；午休/15点/缺口截图验收 |
| P4 接回五合一 | 新数据源adapter，原Premium Engine保留对照，显式切换 | 对照通过后替换溢价分母；原策略阈值单位和时间窗测试通过 |

不能只凭计算微基准承诺实时容量。端到端还要测 SDK 推送/JSON解码/更新缓存/批量计算/落盘/SSE；目标每组 P99 明显小于3秒（建议先定100ms软目标），稳定内存、有界队列、无漏组。验收先shadow，不在单元测试或探针里触发申赎/订单。

P1 需明确的是逐基金结算通道/方向适用性以及真实 feed 接入方式；本轮计算库用显式参数支持这些选择，不以猜测写入生产。此阶段不需要修改五合一仓库。
